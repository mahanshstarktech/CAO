Memory Hierarchy

85% — Part B 2024

What is Memory Hierarchy?

The memory hierarchy is the organization of different types of memory in a computer system, arranged from the fastest/most expensive/smallest at the top to the slowest/cheapest/largest at the bottom. The key insight is: programs exhibit locality — they use a small subset of memory most of the time. By keeping the most-used data in fast memory (cache/registers), we approach the speed of fast memory at the cost of slow memory.

Memory hierarchy is like your study space. Your desk (registers) is tiny but you can grab anything instantly. Your bookshelf (cache) is slightly farther — seconds to reach. Your home library (RAM) takes minutes. A storage room (hard disk) takes much longer. An off-site warehouse (cloud/tape) takes hours. You organize your work so the most needed books are on your desk. If the book isn't on your desk, you get it from the shelf (cache hit/miss).
Fig 1.1 — Memory Hierarchy: Registers (fastest) → Cache → RAM → Disk → Tape (slowest). Speed decreases, capacity increases, cost-per-bit decreases as we go down.

Locality of Reference — Why the Hierarchy Works

The memory hierarchy exploits two principles of locality of reference:

  • Temporal Locality: A recently accessed memory location is likely to be accessed again soon (e.g., loop counter — accessed every iteration).
  • Spatial Locality: When a memory location is accessed, nearby locations are likely to be accessed soon (e.g., array traversal — sequential elements accessed one after another).
Memory Hierarchy Performance Metrics
Hit Ratio (h): h = (Number of cache hits) / (Total memory accesses)
Average Access Time: Tavg = h × Tc + (1-h) × Tm
where Tc = cache access time, Tm = main memory access time
(1-h) = miss rate
Example: h = 0.95, Tc = 5 ns, Tm = 80 ns:
Tavg = 0.95×5 + 0.05×80 = 4.75 + 4 = 8.75 ns
Compare: no cache = 80 ns → with cache = 8.75 ns → ~9× speedup!

Memory Hierarchy:
The memory hierarchy is an organization of memory systems at different speed/cost/capacity levels, designed to provide the user with as much memory as is available in the cheapest technology while operating at the speed offered by the fastest memory.

• Temporal Locality: Recently used data will be used again soon
• Spatial Locality: Data near recently accessed locations will be used soon

Q. What do you mean by Hit Ratio in cache memory?

Hit Ratio (h) in cache memory is the ratio of the number of successful cache accesses (hits) to the total number of memory access requests.

Formula:
h = (Number of cache hits) / (Total memory accesses) = hits / (hits + misses)

Average Access Time:
Tavg = h × Tc + (1 − h) × Tm
where Tc = cache access time, Tm = main memory access time, (1−h) = miss rate

Example: h = 0.9, Tc = 10 ns, Tm = 100 ns
Tavg = 0.9×10 + 0.1×100 = 9 + 10 = 19 ns

A higher hit ratio means better performance. Modern CPUs achieve h ≥ 0.95.

RAM Chip Design — RTU Numerical Method

When a computer needs more memory than a single chip provides, multiple chips are connected together. This requires address decoding to select the right chip.

Imagine each RAM chip is a small notebook with 128 pages (128 locations), each page holding 8 bits (1 byte). If you need a 4096-page notebook (4096 bytes), you need 4096/128 = 32 small notebooks. You need a "manager" (address decoder) who, given a page number, finds which notebook and which page within that notebook to look at.
RAM Chip Design Formulas — Master These for Part C Q5
Given: Each chip = W words × B bits
Total memory required = N bytes (or words)
(i) Number of chips = Total memory ÷ Per-chip memory
= N bytes ÷ (W × B / 8) bytes
(ii) Total address bus lines = log₂(total words)
Lines within each chip (word select) = log₂(W) [these are COMMON to all chips]
Lines for chip select = log₂(total chips) = log₂(N/W)
(iii) Chip select lines = log₂(number of chips)
(iv) Size of decoder = chip_select_lines × number_of_chips
(a k-to-2^k decoder, where k = chip select bits)

RTU 2022 & 2025 Example — 2048 bytes from 128×8 chips

Worked Example — 2048 bytes from 128×8 RAM chips
Each chip: 128 words × 8 bits (= 128 bytes per chip)
Total memory: 2048 bytes
(i) Number of chips = 2048 / 128 = 16 chips
(ii) Total address lines = log₂(2048) = 11 lines
Within each chip (word select): log₂(128) = 7 lines (common to ALL chips)
For chip select: 11 - 7 = 4 lines (select 1 of 16 chips)
Verify: 2^4 = 16 chips ✓
(iii) Chip select lines = 4 lines (decoded to select one of 16 chips)
(iv) Decoder size = 4-to-16 decoder (4 input lines → 16 output chip-select lines)
Memory map: Address 0x000–0x07F → Chip 1 | 0x080–0x0FF → Chip 2 | ... | 0x780–0x7FF → Chip 16

Q. What is auxiliary memory?
2024 Part A Q10 · 2 marks ⭐⭐Auxiliary Memory🔮 HIGH 2026 Part A
Auxiliary memory (secondary memory or mass storage) is non-volatile storage that holds large amounts of data permanently, even when the computer is powered off.

Characteristics:
• Non-volatile (data persists without power)
• Much larger capacity than main memory (GBs to TBs)
• Much slower access times than RAM (milliseconds vs nanoseconds)
• Lower cost per bit than RAM

Types:
1. Magnetic Hard Disk (HDD): Rotating platters with read/write heads. Organized into tracks, cylinders, and sectors. Access time = seek time + rotational latency + transfer time.
2. Solid State Drive (SSD): Flash memory chips. No moving parts → faster, more durable, more expensive per GB.
3. Magnetic Tape: Sequential access. Used for backup and archiving.
4. Optical Disks (CD/DVD/Blu-ray): Laser-read storage.

Use: Stores the operating system, user files, databases, and program files. Data must be loaded into main memory before the CPU can process it.

Magnetic Disk Organization

A magnetic disk (HDD) stores data on concentric circles called tracks on a rotating magnetic platter. Each track is divided into sectors (smallest addressable unit, typically 512 bytes). Multiple platters share a common spindle; the set of tracks at the same radial position on all platters is called a cylinder.

Disk Access Time Formula
Total Access Time = Seek Time + Rotational Latency + Transfer Time
Seek Time: Time to move read/write head to correct TRACK
Typical: 3–15 ms (average ≈ 4–8 ms)
Rotational Latency: Time for correct SECTOR to rotate under head
Average = half rotation time
For 7200 RPM: rotation time = 60/7200 = 8.33 ms → avg latency = 4.17 ms
Transfer Time: Time to read/write the data once head is positioned
Transfer time = sector_size / (data_rate)
Seek time dominates → place related data in same cylinder to minimize seeks

Associative Memory (Content-Addressable Memory)

72%

What is Associative Memory?

Associative memory (CAM — Content-Addressable Memory) is a special type of memory where you look up data by its CONTENT, not by its address. You provide a search key (partial content), and the hardware returns all matching entries simultaneously by searching the entire memory in parallel.

Regular memory is like a library where you look up a book by its shelf number (address). Associative memory is like a search engine — you say "show me all books about computers written in 1990" and it searches ALL books simultaneously and returns all matches in one step. This is how a cache looks up whether it contains a particular block — it compares the tag field with all cache entries in parallel.
Associative Memory Components
Key Register (Argument): holds the search pattern (query)
Mask Register: specifies which bits of the key to compare (1=compare, 0=ignore)
Match Register: 1 bit per word — set to 1 if that word matches the key
Read Register: output of the matching word(s)
Operation: For each word in memory, simultaneously compare
(Key AND Mask) with (Memory_word AND Mask)
→ If all compared bits match → set corresponding Match bit to 1
Used in: TLB (Translation Lookaside Buffer), cache tag comparison, network routing tables
🔗
Connection — Associative Memory → Cache + Virtual Memory

Associative memory is NOT just a standalone concept — it is the HARDWARE MECHANISM inside fully associative cache and the TLB (Translation Lookaside Buffer). When your CPU checks if a memory block is in the cache (fully associative), it uses associative memory hardware to compare the tag with ALL cache lines simultaneously. The TLB (which maps virtual to physical pages) is also a small associative memory. Understanding CAM = understanding how cache lookups work!

Why Cache Memory?

Cache memory is a small, high-speed memory that sits between the CPU and main memory. It stores copies of frequently accessed memory blocks. Because of temporal and spatial locality, most memory accesses find what they need in cache (hit) — only occasionally needing to access slow main memory (miss).

Cache is the CPU's personal notepad. Main memory is a huge filing cabinet across the room. When the CPU needs data, it first checks its notepad (cache). If found — great, instant access! If not — it has to walk to the filing cabinet (main memory), which takes much longer. But it also writes the retrieved data on the notepad for future use. After a while, the notepad contains all the frequently-used data — the CPU rarely needs to walk to the filing cabinet anymore.
Cache Terminology
Block (Cache Line): Unit of transfer between cache and memory (typically 64 bytes)
Tag: The part of the memory address stored in cache to identify which block
Valid bit: 1 = cache line contains valid data | 0 = empty/invalid
Hit: Requested data found in cache
Miss: Requested data NOT in cache → fetch from main memory
Hit ratio (h): hits / (hits + misses)
Cache size: typically 32 KB (L1) to 8 MB (L3)

Direct Mapping Cache

88%

How Direct Mapping Works

In direct mapping, each block in main memory can go to exactly ONE specific cache line. The mapping is fixed: cache_line = memory_block_number mod number_of_cache_lines.

Direct mapping is like assigned parking spots. Every car (memory block) has exactly ONE allowed parking spot (cache line) — there's no choice. Block 0 goes to spot 0, block 8 goes to spot 0, block 16 goes to spot 0... If two blocks that both map to the same spot are needed alternately, constant eviction and refilling occurs (called thrashing).
Direct Mapping — Address Division
Memory address is divided into 3 fields:
| TAG | INDEX (cache line number) | BLOCK OFFSET (word within block) |
Block Offset bits: log₂(block_size_in_words) = b bits
Index bits: log₂(number_of_cache_lines) = k bits
Tag bits: total_address_bits - k - b = t bits
Lookup procedure:
1. Extract INDEX from address → go to that cache line
2. Compare TAG in address with TAG stored in that cache line
3. Check Valid bit = 1
4. If TAG matches AND Valid=1 → HIT, use OFFSET to get word
If TAG doesn't match OR Valid=0 → MISS, fetch from memory
Fig 6.1 — Direct Mapping: Address = TAG | INDEX | OFFSET. INDEX selects the cache line; TAG is compared to verify it's the right block.

Direct Mapping Numerical Example

Example: 32KB cache, 64-byte blocks, 32-bit addresses
Cache lines = 32 KB / 64 bytes = 512 lines
Block offset bits = log₂(64) = 6 bits
Index bits = log₂(512) = 9 bits
Tag bits = 32 - 9 - 6 = 17 bits
Address format: [17-bit TAG | 9-bit INDEX | 6-bit OFFSET]
Memory block 0 → cache line 0 (0 mod 512 = 0)
Memory block 512 → cache line 0 (512 mod 512 = 0) ← CONFLICT!
Memory block 1 → cache line 1

Fully Associative Cache Mapping

82%

How Fully Associative Mapping Works

In fully associative mapping, any block of main memory can be placed in ANY cache line. There is NO index field — the entire address (minus the offset) is the tag. The cache uses associative memory hardware to search ALL cache lines simultaneously.

Fully associative is like open parking — no assigned spots. Any car can park in any available spot. This is more flexible (no conflicts), but to find your car, you need to check every parking spot simultaneously (associative search hardware). This is expensive but eliminates conflict misses.
Fully Associative — Address Division
Memory address = | TAG | BLOCK OFFSET |
(no INDEX field)
TAG bits = total_bits - offset_bits
OFFSET bits = log₂(block_size)
Example: 32-bit address, 64-byte blocks:
OFFSET = log₂(64) = 6 bits
TAG = 32 - 6 = 26 bits
Replacement policy (when cache is full):
LRU (Least Recently Used): evict line not used for longest time — most common
FIFO: evict oldest line (first loaded)
Random: evict random line (simple hardware)
Fully associative = most flexible placement, most hardware, used for TLBs (which are small)

Set-Associative Cache Mapping

🔥 90% — Part B 2024, CERTAIN 2026
🔮
2026 Prediction — CERTAIN Part B Q2: Set-associative mapping appeared as Part B Q2 in 2024, absent in 2025. After a one-year gap, this is strongly due to return in 2026. Always include both the address division AND the lookup procedure with a worked numerical example.

How Set-Associative Mapping Works

Set-associative mapping is a compromise between direct and fully associative mapping. The cache is divided into sets, each containing k ways (k cache lines). Each memory block maps to exactly ONE set (like direct mapping) but can go into ANY of the k lines within that set (like fully associative within the set).

Set-associative is like a parking garage with designated FLOORS (sets) but free parking WITHIN each floor (ways). Each car must park on a specific floor (determined by the car's license plate mod number_of_floors), but once on that floor, they can take any available spot. This reduces conflicts (2-4 spots per floor means even if two cars map to the same floor, they rarely conflict) while keeping hardware manageable (only check 2-4 spots, not thousands).
k-Way Set-Associative — Address Division
Address = | TAG | SET INDEX | BLOCK OFFSET |
Number of sets = Cache_size / (k × block_size)
Set index bits = log₂(number of sets)
Block offset bits = log₂(block_size)
Tag bits = address_bits - set_bits - offset_bits
Lookup procedure:
1. Use SET INDEX bits to identify the set
2. Within that set, check ALL k ways simultaneously (compare TAG)
3. If any way's TAG matches AND Valid=1 → HIT
4. If no match → MISS, fetch from memory, use LRU to replace a way

Set-Associative Worked Example

Example: 2-way set-associative, 8 sets, 4-word blocks, 16-bit address
Cache organization: 2 ways × 8 sets × 4 words/block
Total cache: 2 × 8 × 4 = 64 words = 64 words capacity
Address breakdown (16-bit):
Block offset bits = log₂(4) = 2 bits (bits 1-0)
Set index bits = log₂(8) = 3 bits (bits 4-2)
Tag bits = 16 - 3 - 2 = 11 bits (bits 15-5)
Address format: [11-bit TAG | 3-bit SET | 2-bit OFFSET]
Example address: 0x0A3C = 0000 1010 0011 1100
Binary: 0000 1 | 010 | 00 | rest → SET = 011 = set 3 | TAG = 000010 | OFFSET = 00
→ Look in SET 3 (ways 0 and 1), compare TAG=000010 with both ways
Fig 8.1 — 2-Way Set-Associative Cache: SET index selects the set; TAG is compared with BOTH ways in parallel; OFFSET selects word within block.

Set-Associative Mapping:
Set-associative mapping combines the advantages of direct mapping (simple hardware, fast lookup) and fully associative mapping (flexible placement, no conflicts). The cache is divided into sets, each containing k lines (k-way set-associative).

Address Division:
Memory address = | TAG | SET INDEX | BLOCK OFFSET |
• SET INDEX: selects which set to look in
• TAG: compared with all k ways in that set simultaneously
• OFFSET: selects the word within the block

Operation:
1. Use SET field to identify the set (like direct mapping)
2. Compare TAG with all k line tags in that set simultaneously (like fully associative within the set)
3. If any line's TAG matches AND valid bit = 1 → HIT
4. If no match → MISS → fetch from memory, use LRU to replace a line in the set

Example (2-way set-associative):
Cache = 8 sets × 2 ways, block size = 4 words, 12-bit address
Block offset: log₂(4) = 2 bits | Set index: log₂(8) = 3 bits | Tag: 12-2-3 = 7 bits

Address 0x1B4 = 0001 1011 0100
Tag = 0001 101 = 13 | Set = 011 = 3 | Offset = 00
→ Check set 3 (both ways). If way 0 has tag=13, V=1 → HIT in way 0.

Advantage over Direct: Reduces conflict misses (2 blocks can share a set)
Advantage over Fully Associative: Simpler hardware (only k comparators per access)

Virtual Memory

82%

What is Virtual Memory?

Virtual memory is a memory management technique that gives each process the illusion of having a large, private address space (virtual address space) even when physical memory (RAM) may be smaller. It allows programs larger than RAM to run, and enables multiple programs to run simultaneously without interfering with each other.

Virtual memory is like a hotel where guests (programs) each think they have an entire building (virtual address space) to themselves. In reality, the hotel only has 100 rooms (physical RAM). The hotel management (OS) maps each guest's "imagined room numbers" to actual room numbers. If all rooms are full and a guest needs a room, management moves an unused guest's belongings to a storage room (disk/swap space) to free a room — this is a page fault/swap.
Virtual Memory — Key Concepts
Virtual Address: Address used by program (as seen by the process)
Physical Address: Actual address in RAM
Page: Fixed-size unit of virtual address space (typically 4 KB)
Frame: Fixed-size unit of physical memory (same size as page)
Page Table: OS-maintained mapping from virtual page numbers to physical frame numbers
TLB (Translation Lookaside Buffer): Hardware cache for page table entries (associative memory)
Virtual address translation:
Virtual address = [Virtual Page Number | Page Offset]
VPN → Page Table → Physical Frame Number
Physical address = [Frame Number | Page Offset]

Page Fault Handling

A page fault occurs when a program accesses a virtual page that is NOT currently in physical memory (it's on the disk). The OS must: (1) find a free frame or evict an existing page (using LRU), (2) load the required page from disk to RAM, (3) update the page table, (4) resume the program.

Fig 9.1 — Virtual Memory Translation: CPU generates virtual address → TLB lookup (fast) → on miss, check page table → on page fault, load from disk.
Page Table Entry Fields
| Valid | Frame Number | Dirty | Referenced | Protection | ...
Valid (Present) bit: 1 = page is in RAM | 0 = page fault (on disk)
Dirty bit: 1 = page modified since loaded → must write back to disk when evicted
Referenced bit: 1 = page accessed recently (used for LRU)
Protection bits: read/write/execute permissions

What is a Multiprocessor?

A multiprocessor is a system with two or more processors that share memory and I/O facilities, and are controlled by one operating system that provides interaction between processors and programs.

A multiprocessor is like a company with multiple employees (CPUs) sharing the same office building (memory). All employees can access any file cabinet (memory location), but they need to coordinate to avoid conflicts — two people shouldn't edit the same document simultaneously. The manager (OS) and protocols (synchronization) keep everything organized.

Characteristics of Multiprocessors

  1. Multiple CPUs: Two or more physically separate processing units, each with its own registers and local cache.
  2. Shared Memory: Common global memory accessible to all processors (in tightly-coupled systems).
  3. Common I/O: All processors share the same I/O system and secondary storage.
  4. Single OS: One operating system manages all processors and coordinates their activities.
  5. Message Passing or Shared Variables: Processors communicate and synchronize via shared memory variables or message passing.
  6. Parallel Execution: Multiple programs or parts of one program execute simultaneously → increased throughput.
  7. Fault Tolerance: If one processor fails, others can continue operating.

Interprocessor Arbitration

Arbitration is the mechanism for resolving conflicts when multiple processors try to access the same shared resource (memory bus) simultaneously. Methods:

  • Daisy Chain Arbitration: Grant signal propagates through processors in chain order (same as priority interrupt).
  • Centralized Parallel Arbitration: All processors request bus simultaneously; a central arbiter selects one based on priority.
  • Distributed Arbitration: Each processor broadcasts its request; all processors resolve contention by looking at all requests together (e.g., lowest ID wins).

Interprocessor Synchronization

When multiple processors share data, synchronization prevents race conditions. Key primitives:

Synchronization Mechanisms
Semaphore: Binary (mutex) or counting semaphore — P (wait/lock) and V (signal/unlock)
Spin Lock: Processor busy-waits (loops) testing a variable until lock is available
Barrier: All processors must reach the barrier before any can proceed
Test-and-Set: Atomic instruction — reads and sets a variable in one uninterruptible step

The Cache Coherence Problem

In a multiprocessor system, each processor has its own private cache. When multiple processors cache copies of the same memory block, and one processor modifies its copy, the other caches have stale (outdated) data. This inconsistency is the cache coherence problem.

Cache coherence is the "stale newspaper" problem in a multiprocessor. Imagine 3 people (processors) each have a photocopy (cache) of the same newspaper page. Person 1 marks a correction on their copy. Now Person 2 and 3 still have the old, incorrect version. They don't know about the update. If someone asks Person 2 for information, they give stale data. In a computer, this causes INCORRECT results — different processors see different values for the same variable.
Cache Coherence — Example of the Problem
Initial: Memory[X] = 5
P1 reads X: P1's cache = 5
P2 reads X: P2's cache = 5
P1 writes X = 10: P1's cache = 10, Memory might still be 5 (write-back)
P2 reads X: P2's cache = 5 → WRONG! (should be 10)
→ Cache incoherence!

Cache Coherence Protocols

1. Write-Invalidate Protocol

When a processor writes to a cache block, it invalidates all other caches that have copies of that block. The next time other processors try to read that block, they get a cache miss and fetch the updated value from memory (or directly from the writing processor's cache).

Write-Invalidate Operation
P1 writes X = 10:
→ Broadcasts invalidation message on bus: "Everyone: invalidate your copy of block containing X"
→ P2, P3 see the message: mark their cached copy of X as INVALID
→ Next time P2 reads X: cache miss → gets the new value 10 from P1's cache or memory
Used by: most modern CPU cache protocols. Generates fewer bus transactions than write-update for writes followed by multiple reads.

2. Write-Update Protocol

When a processor writes to a block, it updates all other cached copies with the new value immediately (broadcast update).

Write-Update Operation
P1 writes X = 10:
→ Broadcasts update: "Everyone: update your cached copy of X to 10"
→ P2, P3 immediately update their cache: now all have X = 10
Advantage: No misses after update. Disadvantage: High bus traffic for every write. Less common than write-invalidate.

MESI Protocol — 4-State Cache Coherence

The MESI protocol is the most widely used cache coherence protocol. Each cache line can be in one of four states:

StateMeaningData valid?Other caches have copy?Memory up to date?
ModifiedOnly this cache has the block, and it has been modified (dirty)YesNoNo (must write back)
ExclusiveOnly this cache has the block, not modified (clean)YesNoYes
SharedMultiple caches may have this block (read-only)YesYesYes
InvalidCache line is invalid — data not usableNoUnknownUnknown
⚡
MESI Memory Trick — "My Exclusive Shared Invalid"

Modified = "Mine! Dirty — I changed it, memory is outdated, must write back if evicted"
Exclusive = "Mine alone! Clean — I have the only copy, memory is current"
Shared = "Shared read-only — multiple caches have it, memory is current"
Invalid = "Unusable — my copy is stale or was invalidated"

For exam: "Explain MESI protocol" = define each state with conditions and draw the state transition diagram showing when states change (e.g., S→M on write, M→I on another processor's read-invalidate request).

Cache Coherence Problem:
In a multiprocessor system, each processor has a private cache. When multiple processors cache copies of the same memory block and one processor modifies its copy, the other caches contain stale (outdated) data. This inconsistency is the cache coherence problem.

Example:
Initial: Memory[A] = 100
Step 1: P1 reads A → P1's cache: A=100; Memory: A=100
Step 2: P2 reads A → P2's cache: A=100; Memory: A=100
Step 3: P1 writes A = 200 → P1's cache: A=200; Memory may still have A=100
Step 4: P2 reads A → gets A=100 from its cache → WRONG! (should be 200)
Result: P1 and P2 have inconsistent views of A → incorrect program behavior

Solutions — Cache Coherence Protocols:

1. Write-Invalidate Protocol:
When P1 writes, it broadcasts an invalidation to the bus. All other caches that have the same block mark it INVALID. On P2's next read, it gets a cache miss and fetches the updated value.
Advantage: Fewer bus transactions for writes. Most common (used in Intel/AMD CPUs).

2. Write-Update Protocol:
When P1 writes, it immediately broadcasts the new value. All caches with that block update to the new value.
Advantage: No subsequent misses. Disadvantage: High bus traffic per write.

MESI Protocol:
A widely-used write-invalidate protocol where each cache line is in one of four states:
• M (Modified): Only this cache, data is modified, memory outdated
• E (Exclusive): Only this cache, data not modified, memory current
• S (Shared): Multiple caches may have copy, all clean
• I (Invalid): Data not usable, must refetch

State transitions ensure coherence: when one cache moves to M, all other caches move their copy to I. When multiple caches share (S), no one can write without first invalidating others.

What are Shared Memory Multiprocessors?

Shared memory multiprocessors (also called tightly-coupled multiprocessors) have all processors connected to a single, common physical memory through an interconnection network. Any processor can access any memory location using LOAD and STORE instructions.

UMA vs NUMA
UMA (Uniform Memory Access):
All processors have equal access time to all memory locations
Simple bus-based interconnect (symmetric multiprocessors — SMP)
Scalability limited (bus becomes bottleneck beyond ~8 CPUs)
Example: Intel Xeon dual-socket server, AMD dual-socket workstation
NUMA (Non-Uniform Memory Access):
Each CPU has local memory (fast access) and remote memory (slow access)
Better scalability (no single shared bus)
OS and programs must be NUMA-aware for best performance
Example: AMD EPYC (multiple dies with local DRAM), large Intel servers
