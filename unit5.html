Addition and Subtraction

80%

Binary Addition and Subtraction with 2's Complement

Modern computers perform all arithmetic using 2's complement representation for signed integers. Addition and subtraction are unified into a single operation: subtraction A − B = A + (2's complement of B).

Instead of building a separate subtraction circuit, computers always ADD. To subtract B from A, they just flip all bits of B and add 1 (making it negative in 2's complement), then add to A. One adder circuit does BOTH add and subtract — saving hardware! This is why in the basic computer, subtraction is: CMA (complement), INC (add 1), ADD.
Addition and Subtraction Rules
Addition: A + B → binary addition directly
Subtraction: A - B → A + (2's complement of B)
= A + B' + 1 (B' = 1's complement, +1 = 2's complement)
Overflow Detection (signed numbers):
Overflow = Carry into MSB ⊕ Carry out of MSB
If both operands +ve and result –ve → Overflow!
If both operands –ve and result +ve → Overflow!
Range for n-bit signed (2's complement): −2^(n−1) to +2^(n−1)−1
RTU pattern: overflow + addition examples appear in Part A (unsigned/signed addition)

Hardware for Binary Addition

A full adder adds three 1-bit inputs (A, B, Cin) producing a sum bit and carry-out. An n-bit ripple carry adder chains n full adders. The carry propagates from LSB to MSB — slow for large n but simple to build.

Full Adder Equations
Sum = A ⊕ B ⊕ Cin (XOR of all three inputs)
Carry = (A AND B) OR (B AND Cin) OR (A AND Cin) (majority function)

Overflow Detection Trick

Overflow can only happen when both operands have the SAME sign:
• Positive + Positive = Negative result → Overflow!
• Negative + Negative = Positive result → Overflow!
• Positive + Negative = never overflow (result magnitude is between the two)

Hardware: V = C₇ ⊕ C₈ where C₇ = carry INTO sign bit, C₈ = carry OUT of sign bit. If V=1, overflow occurred.

Booth's Multiplication Algorithm

🔥 98% — 100% of ALL Papers
🔮

Why Booth's Algorithm?

Booth's Algorithm multiplies two signed binary numbers in 2's complement representation efficiently. It handles both positive and negative numbers with the SAME hardware, using add and subtract operations, and is faster for numbers with consecutive 1s (it converts 0111 = +7 to 1000−1, needing only 2 operations instead of 3).

Booth's Algorithm is a clever trick to multiply signed binary numbers. Instead of naively adding the multiplicand for each 1-bit in the multiplier (which doesn't work for negative numbers), it looks at PAIRS of bits as they shift in. When it sees a 01 transition (0 before, 1 now), it adds. When it sees 10 transition, it subtracts. For same bits (00 or 11), it just shifts. This works perfectly for signed numbers without any special cases.

Booth's Algorithm — Components

Registers and Initial Setup
A register: n+1 bits (accumulator — starts at 0, holds partial product)
Q register: n bits (starts with multiplier value)
Q₋₁ bit: 1 extra bit (starts at 0 — represents the bit "shifted out" from Q)
M register: n bits (holds multiplicand — does NOT change)
Count: n (number of iterations = number of bits in multiplier)
In each iteration, look at Q₀ (LSB of Q) and Q₋₁:
Q₀ Q₋₁ = 10 → A ← A − M (subtract: add 2's complement of M)
Q₀ Q₋₁ = 01 → A ← A + M (add M)
Q₀ Q₋₁ = 00 → do nothing (shift only)
Q₀ Q₋₁ = 11 → do nothing (shift only)
Then: arithmetic right shift (AQ) ← shr(AQ) — sign bit of A is preserved!
After n iterations: result = A concatenated with Q (A is MSBs, Q is LSBs)

Division Algorithms

82% — Part B 2025

Integer Division — Restoring Method

Integer division produces a quotient and a remainder. The restoring division algorithm is the straightforward method: try subtracting the divisor from the partial remainder; if the result is negative, "restore" (add back the divisor) and record quotient bit 0; if positive, keep the subtraction and record quotient bit 1.

Division is repeated subtraction. Long division in binary: shift the dividend bit by bit, try to subtract the divisor from the partial result. If it fits (result ≥ 0), write a 1 in the quotient. If it doesn't fit (result < 0), restore (undo the subtraction) and write a 0. Repeat for each bit.
Restoring Division — Setup
A register: n+1 bits (partial remainder — initialized to 0)
Q register: n bits (starts with dividend — will contain quotient at end)
M register: n bits (divisor — does not change)
Count: n iterations
Each iteration:
1. Left shift AQ by 1 position (logical shift left)
2. A ← A − M (try subtraction)
3. If A ≥ 0 (MSB = 0): Q₀ ← 1 (quotient bit = 1, keep subtraction)
If A < 0 (MSB = 1): Q₀ ← 0 (quotient bit = 0, RESTORE: A ← A + M)
After n iterations: Q = quotient, A = remainder

Non-Restoring Division

The non-restoring method is more efficient — it avoids the restore step by combining the subtraction and the re-addition into a single decision in the next step.

Non-Restoring Division Rule
If previous step set Q₀=0 (partial remainder was negative):
→ This step: left shift AQ, then A ← A + M (add instead of subtract)
If previous step set Q₀=1 (partial remainder was positive):
→ This step: left shift AQ, then A ← A − M (subtract as normal)
After last step: if A < 0, restore once: A ← A + M
Saves one addition step per negative result compared to restoring. Used in practice for higher speed.

Division Numerical Example

Divide +7 ÷ +3 (4-bit restoring division)
Dividend = 0111 (7), Divisor = 0011 (3)
Initial: A = 00000, Q = 0111, M = 0011, −M (2's comp) = 1101
Step 1: Shift left: A=00001, Q=1110 → A←A−M: 00001+11101=00110+carry → A=00110, MSB=0
MSB=0 → positive → Q₀=1 → A stays = 00110, Q=1110 + Q₀=1 → Q=1111...
Wait: set LSB of Q to quotient bit: Q₀←1 → Q=1111? No...
SIMPLIFIED METHOD: (4 steps, result: Q = quotient = 0010 = 2, A = remainder = 0001 = 1)
Verification: 7 ÷ 3 = 2 remainder 1 ✓

Floating Point Arithmetic Operations

80%

Floating Point Number Format (Review)

A floating-point number is stored as: Sign (1 bit) | Exponent (biased) | Mantissa (fraction). Value = (−1)^S × 1.M × 2^(E−bias).

🔗
Connection — Unit 2 (Floating Point) + Unit 4 (Arithmetic Pipeline) → Unit 5

In Unit 2, you learned how to REPRESENT floating-point numbers (sign, exponent, mantissa). In Unit 4, you saw the 4-stage arithmetic pipeline that computes floating-point addition. In Unit 5, you now learn the ACTUAL RULES for performing floating-point arithmetic operations — the algorithm that pipeline implements step by step.

Floating Point Addition/Subtraction — Steps

1
Check for zeros: If either operand is 0, return the other operand immediately.
2
Align exponents: Compare exponents. Right-shift the mantissa of the number with the smaller exponent by |E₁ − E₂| positions, and set both exponents equal.
3
Add/Subtract mantissas: Perform binary addition or subtraction on the aligned mantissas.
4
Normalize the result: Adjust mantissa so it has the form 1.xxxxx (leading 1 before binary point). Shift mantissa left or right, adjusting the exponent accordingly.
5
Check for overflow/underflow: If exponent exceeds max → overflow. If exponent is less than min → underflow (set to zero).
6
Round/Truncate: If mantissa exceeds available bits, apply rounding (round to nearest, round toward zero, etc.).
Floating Point Addition Example
A = 1.010 × 2³ = 10.10 (decimal: 10.5 approx)
B = 1.110 × 2¹ = 0.01110 (after alignment)
Step 1: Align — B has smaller exponent (1 vs 3, diff=2)
Shift B right 2: 1.110 × 2¹ → 0.01110 × 2³
Step 2: Add mantissas (both × 2³):
1.01000 + 0.01110 = 1.10110
Step 3: Result = 1.10110 × 2³ (already normalized)

Floating Point Multiplication and Division

FP Multiplication and Division Rules
Multiplication: (M₁ × 2^E₁) × (M₂ × 2^E₂)
= (M₁ × M₂) × 2^(E₁ + E₂)
Steps: (1) Add exponents (subtract bias once) (2) Multiply mantissas (3) Normalize
Division: (M₁ × 2^E₁) ÷ (M₂ × 2^E₂)
= (M₁ ÷ M₂) × 2^(E₁ - E₂)
Steps: (1) Subtract exponents (add bias once) (2) Divide mantissas (3) Normalize

Decimal Arithmetic Unit

68%

BCD Arithmetic

A Decimal Arithmetic Unit performs arithmetic directly on BCD (Binary Coded Decimal) numbers — where each decimal digit 0–9 is represented by 4 binary bits (0000–1001). This avoids the decimal-to-binary conversion overhead for decimal-heavy applications (banks, calculators).

A decimal arithmetic unit is like a cash register that works in "dollars and cents" rather than converting to binary first. Each decimal digit (0-9) is stored as its 4-bit binary equivalent. When two BCD digits are added and the result exceeds 9 (invalid BCD), a correction of +6 (0110) is added to skip the invalid hex digits A-F and produce the correct BCD result with carry.
BCD Addition — Correction Rule
Normal binary addition of two BCD digits (each 0000–1001):
If result ≤ 9 (1001): result is valid BCD → keep as is
If result > 9 (1010–1111): invalid BCD → add 6 (0110) to correct
Also add 6 if binary addition produced a carry out.
Example: 5 + 8 = 13 (decimal) = 0101 + 1000 = 1101 (binary = 13 decimal, BUT invalid BCD)
Correction: 1101 + 0110 = 10011 → carry=1, result=0011 → BCD = 1 0011 = "13" ✓
Example: 5 + 3 = 8 = 0101 + 0011 = 1000 → 8 ≤ 9, valid BCD, no correction needed ✓

Input-Output Interface

80%

What is an I/O Interface?

An I/O interface (also called I/O controller or device controller) acts as a bridge between the CPU/memory and the peripheral devices. It handles the electrical, timing, and protocol differences between the fast CPU and the slow I/O devices.

The I/O interface is like a hotel front desk. The guests (CPU) don't speak to the kitchen staff (devices) directly — the front desk (interface) takes the order, translates it to kitchen language, waits for the food, and delivers it to the guest. The CPU doesn't need to know how a disk rotates or how a printer works — the interface handles all that.
I/O Interface Components
Data Register: buffers data between CPU and device (often 8-bit for character I/O)
Status Register: flags indicating device state (BUSY, DONE, ERROR)
Control Register: CPU writes commands here (start, stop, type of operation)
Address Decoder: selects which I/O port when CPU sends an I/O address

I/O Port Address vs Memory-Mapped I/O

Asynchronous Data Transfer

72%

Handshaking Protocol

Asynchronous data transfer does not use a shared clock — instead, it uses handshaking signals (REQUEST and ACKNOWLEDGE) to synchronize data transfer between two devices that may operate at different speeds.

Asynchronous transfer is like passing a baton in a relay race where both runners aren't coordinated. The first runner holds out the baton (REQUEST signal = "I have data for you!"). The second runner grabs it and signals back (ACKNOWLEDGE = "I got it!"). Only then does the first runner let go. No shared timing — they coordinate through signals.
Handshaking Protocol — Four-Phase
Phase 1: Source places data on bus AND asserts REQUEST (REQ=1)
Phase 2: Destination reads data, then asserts ACKNOWLEDGE (ACK=1)
Phase 3: Source sees ACK=1 → removes data, deasserts REQ (REQ=0)
Phase 4: Destination sees REQ=0 → deasserts ACK (ACK=0) — ready for next transfer
Both sides wait for the other's signal → no data is missed even if one side is slower
Contrast with synchronous: both devices share a clock and transfer on every clock edge

Priority Interrupt & Daisy Chaining

🔥 88% — Part B 2022, Part A 2025
🔮

For 2026, "Explain priority interrupt and Daisy Chain priority interrupt with block diagram" is a HIGH-probability Part B question. Know both hardware (daisy chain) and software (polling) methods.

What is a Priority Interrupt?

When multiple I/O devices can interrupt the CPU simultaneously, a priority interrupt system determines which device gets served first. Higher-priority devices are serviced before lower-priority ones.

Priority interrupt is like a hospital emergency room triage system. Multiple patients (devices) may need the doctor (CPU) at the same time. The nurse (priority interrupt controller) decides who gets treated first based on urgency. Heart attack patient (disk controller) gets priority over someone with a headache (keyboard). The doctor can still be interrupted mid-treatment if someone more critical arrives.

Daisy Chain Priority Interrupt

In daisy chaining, devices are connected in a chain. The interrupt acknowledge signal (INTA) propagates down the chain from the highest-priority device to the lowest. The first device that has a pending interrupt claims the acknowledge and blocks it from reaching lower-priority devices.

Fig 9.1 — Daisy Chain Priority Interrupt: Device 1 is highest priority (closest to CPU). INTA propagates left-to-right and is absorbed by the first device with a pending request.

Software Polling (Priority Interrupt — Software Method)

In software polling, when an interrupt occurs, the ISR checks each device's status flag in priority order (checking highest-priority device first, lowest last). The first device found with a request is serviced.

Software Polling ISR Structure
Interrupt service routine (when any interrupt occurs):
Check Device 1 status → if request: service Device 1, return
Check Device 2 status → if request: service Device 2, return
Check Device 3 status → if request: service Device 3, return
(... continue for all devices in priority order)
Advantage: Easy to change priorities (just reorder the checks in software)
Disadvantage: Slower (wastes time polling devices that didn't interrupt)

Priority Interrupt:
A priority interrupt is a mechanism that allows multiple devices to interrupt the CPU simultaneously, with the CPU servicing the highest-priority device first.

Need: In a system with multiple I/O devices, all may request service (interrupt) at the same time. Without priority, there's ambiguity. Priority interrupt ensures the most critical device is served first.

Daisy Chain Priority Interrupt:
Hardware-based method where devices are connected in series (a chain). The interrupt acknowledge signal (INTA) propagates from CPU through devices in order of priority (Device 1 = highest priority, closest to CPU).

Operation:
1. Any device with a request raises the common Interrupt Request (INTR) line
2. CPU receives the interrupt, suspends current program, sends INTA
3. INTA propagates down the chain: CPU → Device 1 → Device 2 → ...
4. The first device that has a pending interrupt ABSORBS the INTA signal (does not pass it further)
5. That device sends its interrupt vector to CPU
6. CPU jumps to the correct ISR for that device

Block diagram:
[Draw: CPU on left, INTA line going right through Device 1 → Device 2 → Device 3. Common INTR line (OR of all devices' requests) going into CPU. Each device has: INTA_in → internal logic → INTA_out (if no request, pass through; if request, block and respond)]

Logical diagram of one node:
INTA_out = INTA_in AND (NOT Interrupt_Pending_this_device)
If Interrupt_Pending = 0 (no request): INTA_out = INTA_in (pass through)
If Interrupt_Pending = 1 (has request): INTA_out = 0 (block), AND send vector to CPU
Q. What is a priority interrupt?

A priority interrupt is an interrupt mechanism that assigns a priority level to each interrupt source. When multiple devices interrupt the CPU simultaneously, the device with the highest priority is serviced first.

Key features:
1. Each I/O device has an assigned priority level (higher number or lower = depends on convention)
2. A higher-priority interrupt can even preempt (interrupt) a currently executing ISR for a lower-priority device

• Hardware: Daisy chain — INTA propagates through device chain
• Software: Polling — ISR checks devices in priority order
• Priority encoder (vectored interrupt): Each device has a unique vector that directly calls its ISR

Example: In a computer system, disk controller (high priority) should be served before keyboard (low priority) because disk data may be lost if not read in time.

DMA — Direct Memory Access

🔮

What is DMA?

Direct Memory Access (DMA) allows an I/O device to transfer data directly to/from memory WITHOUT requiring the CPU to handle each byte of data individually. The DMA controller manages the transfer, freeing the CPU to do other useful work.

DMA is like having a delivery courier (DMA controller) handle moving boxes (data) directly from a warehouse (memory) to a truck (I/O device) or vice versa. The manager (CPU) just fills in a shipping form (programs the DMA with source address, destination address, and size), then goes back to other work. The courier makes all the trips independently. When all boxes are moved, the courier taps the manager's shoulder (interrupt) to report completion.

DMA Controller — Block Diagram Components

Fig 10.1 — DMA Controller: Address Register (current memory addr), Word Count Register (bytes remaining), Control Register (read/write mode), Status Register (done/error flags). DMA steals bus cycles from CPU.

DMA Operation — Step by Step

1
CPU programs DMA: CPU writes into DMA registers: (a) Starting memory address (b) Number of words to transfer (c) Direction (read or write) (d) Channel/device number
2
CPU releases bus: DMA requests the system bus from the CPU (Bus Request signal). CPU finishes its current cycle, then grants the bus (Bus Grant signal), and suspends its memory operations.
3
DMA transfers one word (Cycle Stealing): DMA places the memory address on the address bus, transfers one word of data between memory and the I/O device. Increments Address Register, decrements Word Count Register.
4
Return bus to CPU: After each word transfer, DMA releases the bus back to CPU. CPU continues its work. DMA repeats from step 2 for the next word.
5
DMA complete: When Word Count Register reaches 0, DMA has finished. It sends an interrupt to the CPU to report completion. CPU can then process the transferred data.

Cycle Stealing

Cycle stealing is the DMA technique where it "steals" one memory cycle from the CPU to transfer one word. The CPU loses one bus cycle for each word transferred — but the CPU continues executing instructions that don't need memory access (using its registers/cache). This is much more efficient than programmed I/O where the CPU handles every byte.

DMA Transfer Efficiency
With Programmed I/O: CPU executes N instructions PER BYTE transferred → CPU completely occupied
With DMA: CPU loses only 1 bus cycle per word (not byte!) → ~97% CPU utilization maintained
Example: Transfer 1 MB disk block:
Programmed I/O: CPU busy for millions of instructions (disk runs at 50 MB/s → 50,000 I/O per sec per channel)
DMA: CPU continues normal operation, loses <3% bus cycles to DMA

DMA (Direct Memory Access):
DMA is a mechanism that allows an I/O device to transfer data directly to/from main memory without the CPU being involved in each data transfer. This frees the CPU for other tasks while large data blocks are being transferred.

Need for DMA:
Programmed I/O requires the CPU to handle every byte individually. For large transfers (e.g., reading a disk sector of 4 KB), this means thousands of CPU cycles wasted on pure data movement. DMA eliminates this overhead by delegating the transfer to specialized hardware.

DMA Controller Components:
1. Address Register: Holds the current memory address for the transfer. Automatically incremented after each word.
2. Word Count Register: Contains the number of words remaining to transfer. Decremented after each word. Transfer is complete when it reaches 0.
3. Control Register: Programmed by CPU to specify transfer direction (read/write), device channel, and transfer mode.
4. Status Register: Contains flags indicating transfer complete, error conditions, etc.
5. Control Logic: Manages bus request/grant handshake with CPU, generates addresses, and controls the transfer timing.

Operation:
1. CPU programs DMA (start address, word count, direction)
2. DMA requests bus via BUSREQ signal
3. CPU grants bus via BUSACK, releases bus lines
4. DMA transfers one word (memory ↔ device) — cycle stealing
5. DMA releases bus back to CPU
6. Repeat until word count = 0
7. DMA interrupts CPU to signal completion

Advantage: CPU utilization remains ~97-99% during DMA transfers vs nearly 0% during programmed I/O.

Input-Output Processor (IOP) & CPU-IOP Communication

72%

What is an IOP?

An Input-Output Processor (IOP) is a complete processor dedicated exclusively to handling I/O operations. Unlike the DMA controller (which can only transfer data in blocks), the IOP can execute I/O programs independently, handling complex I/O tasks without any CPU intervention.

The IOP is like hiring a full-time I/O manager (a mini-computer) who handles ALL input/output independently. The main boss (CPU) gives the I/O manager a task list (I/O program) and goes back to their own work. The I/O manager handles everything — device handshaking, error checking, buffering, format conversion — and only reports back to the boss when completely done or if there's a problem. More capable than a DMA controller.
IOP vs DMA Comparison
DMA: Simple controller — only transfers data blocks between memory and device
Cannot perform complex operations or execute programs
IOP: Complete processor — can execute I/O programs stored in memory
Can do data formatting, error checking, device control, buffering
Has its own registers, ALU, instruction set

CPU-IOP Communication

CPU-IOP Communication Protocol
1. CPU writes I/O program into memory (start address, devices, operations)
2. CPU sends "Test I/O" instruction → checks if IOP is available
3. CPU sends "Start I/O" instruction to IOP with memory address of I/O program
4. IOP fetches and executes the I/O program independently
5. CPU continues its own program (fully independent of I/O)
6. IOP interrupts CPU when program completes (or encounters error)
7. CPU checks IOP status and processes results
Example: IBM System/360 used I/O channels (IOPs) — each channel could handle multiple devices

Serial Communication

What is Serial Communication?

Serial communication transmits data one bit at a time over a single wire (or pair of wires), rather than multiple bits simultaneously (parallel). While slower per-bit, serial is cheaper, more reliable for long distances, and is the basis of USB, Ethernet, RS-232, and most modern I/O standards.

Serial communication is like a queue of people going through a single door one at a time. Parallel is like multiple doors — faster but more expensive infrastructure. For short distances on a chip, parallel is fine. For cables across rooms or buildings, serial is more reliable (no timing skew between 8 wires) and only needs 1-2 wires instead of 8+.

Synchronous Serial Transmission

In synchronous transmission, sender and receiver share a common clock signal. Data is sent continuously as a stream — no start/stop bits per character. Characters are grouped into larger frames with synchronization characters (SYN) at the beginning.

Synchronous Transmission
Frame: | SYN | SYN | DATA | DATA | ... | DATA | Error check |
No start/stop bits for each character → more efficient for large data blocks
Characters per second = Baud Rate / bits per character
Example: 1200 baud, 8-bit characters, synchronous:
Characters/sec = 1200 / 8 = 150 characters/sec
Clock synchronization needed between sender and receiver — clock signal sent separately or embedded

Asynchronous Serial Transmission

In asynchronous transmission, there is NO shared clock. Each character is framed with a start bit (0) and one or more stop bits (1). The start bit signals the beginning of a character; the receiver synchronizes its internal clock to each start bit.

Asynchronous Transmission Frame Structure
Frame: | Start(1 bit=0) | Data (5-8 bits) | Parity (optional, 1 bit) | Stop (1-2 bits=1) |
Characters/sec with 1 stop bit = Baud Rate / (1 + data_bits + parity + 1_stop)
Example: 1200 baud, 8-bit data, no parity, 1 stop bit:
Total bits per character = 1 + 8 + 0 + 1 = 10
Characters/sec = 1200 / 10 = 120 characters/sec
Example: 1200 baud, 8-bit data, no parity, 2 stop bits:
Total bits per character = 1 + 8 + 0 + 2 = 11
Characters/sec = 1200 / 11 ≈ 109 characters/sec
RTU 2023-Aug C-Q5: "How many characters/sec on 1200-baud line?" — asked for all three cases above!

AspectSynchronousAsynchronous

EfficiencyHigher — no per-character overheadLower — 2-3 extra bits per character

Serial Communication:
Serial communication transmits data one bit at a time over a single channel, with bits transmitted sequentially.

Two types:

Total = 10 bits → 120 characters/sec

Asynchronous is simpler (no clock sync needed) but less efficient (+25% overhead per character).
