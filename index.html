📝 Part A — 2 marks (Q1)
What is meant by RISC? Differentiate RISC and CISC.
RISC was Q1 in 2024. Completely absent in 2025. The 2026 ML, ISS, DIP papers all confirmed: topics skipped in 2025 return in 2026. RISC is the single strongest Q1 return candidate.
VERY HIGH confidence

RISC (Reduced Instruction Set Computer): A processor design philosophy that uses a small, highly optimised set of instructions that execute in one clock cycle. All instructions are fixed-length (32 bits), register-to-register, with separate load/store for memory access.

RISC vs CISC — Comparison Table (write in exam)
Feature | RISC | CISC
──────────────────────────────────────────────
Instruction set| Small, simple | Large, complex
Instruction len| Fixed (32-bit) | Variable length
Cycles/instr | 1 cycle | Multiple cycles
Memory access | Load/Store only | Any instruction
Registers | Many (32+) | Few (8–16)
Pipeline | Easily pipelined | Difficult to pipeline
Control unit | Hardwired | Microprogrammed
Examples | ARM, MIPS, SPARC | x86, 8051, VAX

Layman: CISC is like a Swiss Army knife — many specialised tools but complex. RISC is like a plain sharp knife — fewer tools but ultra-fast at what it does.

📝 Part A — 2 marks (Q2)
What is an instruction cycle? Explain its phases briefly.
Instruction cycle appeared as Q4 in 2024 and was absent in 2025. Core Unit 1 concept — after one-year gap it is strongly due. The 2023-Aug paper had a full AND instruction cycle execution as Part C Q1.
HIGH confidence

The instruction cycle is the complete process a CPU follows to fetch, decode, and execute one instruction. It repeats for every instruction in a program.

Instruction Cycle — Phases
Phase 1 — FETCH: PC → MAR; Memory[MAR] → MDR; MDR → IR; PC ← PC+1
Phase 2 — DECODE: Control unit decodes opcode in IR
Phase 3 — EXECUTE: ALU performs operation; result stored in register/memory
Phase 4 — WRITE: Result written back; interrupt check
PC=Program Counter | MAR=Memory Address Register | MDR=Memory Data Register | IR=Instruction Register
📝 Part A — 2 marks (Q3)
What is immediate addressing mode? (OR Register addressing mode)
Immediate addressing mode was Q3 in 2025 — may repeat in a different phrasing. Addressing modes are a consistent Part A theme. Prepare all 7 modes briefly.
HIGH confidence

Immediate Addressing Mode: The operand is contained directly within the instruction itself — no memory access needed for the operand.

ADD R1, #25 ← #25 is the immediate operand (embedded in instruction)
Effective Address: Not applicable — operand IS the address field value
Advantage: Fast — no extra memory access | Disadvantage: Operand size limited to instruction field width

All 7 Addressing Modes (memorise for Part A):

  • Implied/Implicit: Operand implied by opcode (e.g., CLA — clear accumulator)
  • Immediate: Operand in instruction (ADD #5)
  • Register: Operand in a register (ADD R1, R2)
  • Direct: Address field holds operand address (ADD 500)
  • Indirect: Address field holds address of address (ADD @500)
  • Relative: EA = PC + offset (used in branch instructions)
  • Index: EA = Index Register + displacement
📝 Part A — 2 marks (Q4)
What are the major characteristics of a pipeline?
Present as Q4 in 2025. Pipelining is a central CAO topic tested in Part A (characteristics), Part B (arithmetic pipeline), and Part C (speedup calculations). This phrasing is likely retained in 2026.
HIGH confidence

A pipeline is a technique where multiple instructions are overlapped in execution, like an assembly line. Key characteristics:

  • Throughput: Number of tasks completed per unit time. Maximised when all stages are busy.
  • Speedup: Ratio of non-pipelined time to pipelined time. Ideal speedup = number of stages k.
  • Efficiency: Speedup / Number of stages. Ideal efficiency = 1 (100%).
  • Latency: Time for one task to complete from start to finish = k × clock period.
  • Hazards: Conditions that prevent next instruction from executing — Data, Structural, Control hazards.
Pipeline Speedup Formula
Speedup = (n × k) / (k + n - 1)
As n → ∞: Speedup → k (ideal speedup = number of stages k)
n = number of tasks | k = number of pipeline stages
📝 Part A — 2 marks (Q5)
Define a bus. What are the types of buses in a computer?
Bus was Q5 in 2024 and absent in 2025. The 2022 paper covered bus system extensively in Part C (common bus with multiplexers). After one-year absence, bus returns in 2026.
HIGH confidence

A bus is a shared communication pathway consisting of multiple parallel wires connecting two or more functional units in a computer system. All devices share the same set of lines for communication.

  • Data Bus: Transfers actual data between processor, memory, and I/O devices. Bidirectional. Width = word size (8, 16, 32, or 64 bits).
  • Address Bus: Carries memory addresses from CPU to memory/I/O. Unidirectional. Width determines addressable memory (2^n bytes for n-bit address bus).
  • Control Bus: Carries control signals — Read/Write, Interrupt, Clock, Reset. Both directions.
📝 Part A — 2 marks (Q6)
What is a micro-operation? Give examples of register transfer micro-operations.
Micro-operation was Q6 in 2024 and absent in 2025. The 2022 paper had register transfer hardware diagram. Micro-operations are fundamental to RTU's CAO syllabus and strongly due after one-year gap.
HIGH confidence

A micro-operation is an elementary operation performed by a digital computer during one clock pulse on data stored in registers. It is the smallest unit of operation that can be controlled by the control unit.

Types of Micro-operations
1. Register Transfer: R2 ← R1 (copy R1 into R2)
2. Arithmetic: R3 ← R1 + R2 (add registers)
3. Logic: R1 ← R1 XOR R2 (bitwise XOR)
4. Shift: R1 ← shl R1 (shift left)
RTL Notation: Conditional — P: R1 ← R2 (execute only if control signal P = 1)

Explain fixed point representation (OR represent a number in 2's complement)

HIGH confidence

Fixed Point Representation: A number representation where the binary point (decimal point in binary) is assumed to be at a fixed position — either extreme left (fraction) or extreme right (integer).

Signed Number Representations — 3 Forms (for n-bit word)
Example: represent -13 in 8 bits
+13 in binary: 0 0001101
Signed Magnitude: 1 0001101 ← flip MSB to 1
1's Complement: 1 1110010 ← flip all bits

2's Complement is used in all modern computers — it allows subtraction using addition and has only one representation of zero
📝 Part A — 2 marks (Q8)
What do you mean by parallel processing?
Parallel processing appeared in 2022 (Q6) and 2024 (Q8) but absent in 2025. With Flynn's taxonomy appearing in two consecutive Part C questions (2024, 2025), parallel processing in Part A is a natural companion question for 2026.
HIGH confidence

Parallel processing is a mode of computer operation in which multiple processors execute two or more tasks simultaneously, reducing overall execution time. It is the use of multiple processing elements concurrently to solve a problem faster.

  • Instruction-level parallelism: Pipeline multiple instructions simultaneously
  • Data parallelism: Same operation on multiple data items (SIMD)
  • Task parallelism: Different tasks executed on different processors simultaneously

Classifications by Flynn's Taxonomy: SISD (single processor), SIMD (vector processors), MISD (rare), MIMD (multiprocessors — most common today).

📝 Part A — 2 marks (Q9)
Describe a subroutine. What is the role of a stack in subroutine calls?
Subroutine appeared in 2022 (Q3) and 2025 (Q9) — present in two non-consecutive papers. This alternating pattern and consistent presence makes subroutine a near-certain 2026 Part A question.
VERY HIGH confidence

A subroutine (also called a procedure or function) is a set of program instructions that performs a specific task and can be called from multiple points in a program. It saves memory and enables modular programming.

Stack Role in Subroutine Calls
CALL instruction: Push return address onto stack → Jump to subroutine
Inside subroutine: May push registers onto stack (to save caller state)
RETURN instruction: Pop return address from stack → Continue from caller
Stack = LIFO (Last In, First Out) structure. SP = Stack Pointer register. Enables nested subroutine calls because each call saves its return address independently.
📝 Part A — 2 marks (Q10)
What is cache memory? What is Hit Ratio?
Hit Ratio appeared in 2022 (Q4) and cache memory was Part B Q6 in 2025. Cache is the most consistently tested CAO topic across all parts — it will appear somewhere in every 2026 paper.
CERTAIN

Cache memory is a small, extremely fast (SRAM-based) memory placed between the CPU and main memory (DRAM). It stores copies of frequently accessed data and instructions so the CPU can access them quickly without waiting for slower main memory.

Hit Ratio Formula
H = Hit Ratio = (Number of cache hits) / (Total memory accesses)
T_avg = H × T_cache + (1−H) × T_main
Example: H=0.9, T_cache=10ns, T_main=100ns
T_avg = 0.9×10 + 0.1×100 = 9+10 = 19 ns
Hit = data found in cache | Miss = data not found → access main memory | Higher H → faster average access time

Functional Units of a Computer: A computer system consists of five fundamental units that work together:

  • Input Unit: Accepts data from user (keyboard, mouse, scanner). Converts to binary and sends to memory.

📋 Part B — 4 marks (Q2)
Explain set-associative mapping with a suitable example.
Set-associative mapping appeared in 2024 Part B Q2 and was absent in 2025. The 2022 paper covered all three mapping types in Part C. For 2026, set-associative as a standalone Part B question (as in 2024) is the predicted format.
HIGH confidence

Set-Associative Mapping is a compromise between direct mapping (simple but conflict-prone) and fully associative mapping (flexible but expensive). The cache is divided into sets, each containing k lines. A main memory block maps to exactly ONE set (like direct mapping) but can go into ANY of the k lines within that set (like associative).

Set-Associative Mapping — Address Division
Main Memory Address = Tag | Set Number | Block Offset
Number of sets (s) = Cache size / (k × block size)
Set number = (Block number) mod (number of sets)
Tag = remaining high-order bits of block number
k-way set associative = k lines per set | Common: 2-way, 4-way, 8-way

Example — 2-way Set Associative:

Cache: 8 lines total, organized as 4 sets × 2 lines each. Block size: 4 words. Main memory: 32 blocks.

  • Address bits: 5-bit block number + 2-bit word offset = 7-bit address
  • Set index = block number mod 4 → 2 bits
  • Tag = remaining 3 bits
  • Block 5 (101): Set = 5 mod 4 = 1, Tag = 001 → goes to set 1, either line 0 or line 1
  • Block 9 (1001): Set = 9 mod 4 = 1, Tag = 010 → SAME set 1, other line — no conflict!
📋 Part B — 4 marks (Q3)
What are logical microoperations? Explain applications of logical microoperations.
Logical micro-operations appeared in 2024 (Q4, write 4 logic micro-ops) and 2025 (Q3, explain + applications) — two consecutive years with increasing depth. This is a permanent Part B fixture for 2026.
CERTAIN

Logical microoperations perform bitwise Boolean operations on data stored in registers. Unlike arithmetic operations (which treat the register as a number), logical operations treat each bit independently.

Four Logical Microoperations — Truth Table for each bit
AND: F = A AND B → 1 only if both bits = 1 | RTL: F ← A ∧ B
OR: F = A OR B → 1 if at least one bit = 1 | RTL: F ← A ∨ B
XOR: F = A XOR B → 1 if bits differ | RTL: F ← A ⊕ B
COMP: F = NOT A → complement all bits | RTL: F ← Ā

Applications (know all 4 for exam):

  • Selective Set (using OR): Set specific bits to 1 without affecting others. Mask has 1s where you want to set. Example: Set bits 0 and 2 of R1: R1 ← R1 OR 0101
  • Selective Complement (using XOR): Flip specific bits. Mask has 1s where you want to flip. Example: Complement bits 3 and 5: R1 ← R1 XOR 0101000
  • Selective Clear (using AND): Clear specific bits to 0. Mask has 0s where you want to clear. Example: Clear bits 1 and 3: R1 ← R1 AND 1111...10110101
  • Masking: Isolate specific bits by AND-ing with a mask. Example: Extract lower 4 bits: R1 ← R1 AND 00001111
📋 Part B — 4 marks (Q4)
Differentiate between hardwired control unit and microprogrammed control unit.
Appeared in 2022 (Part B Q6), 2023-Aug Part A Q10, and 2025 (Part B Q4). Present in 3 of 4 papers in some form. Extremely consistent — CERTAIN for 2026. Know speed, flexibility, hardware vs ROM design, and modify-ability.
VERY HIGH confidence
Hardwired vs Microprogrammed Control Unit — Comparison
Feature | Hardwired CU | Microprogrammed CU
─────────────────────────────────────────────────────────
Implementation | Combinational logic | Control memory (ROM)
Speed | Fast (hardware-based) | Slower (memory access)
Flexibility | Rigid — hard to modify | Easy to modify
Design complexity | Complex wiring | Simpler hardware
Cost | Higher (for complex ISA)| Lower (for CISC)
Modification | Requires rewiring | Just update ROM
Debugging | Difficult | Easy (software-like)
Used in | RISC processors | CISC processors
Examples | ARM, MIPS | Intel x86 (historically)

Hardwired CU: Control signals generated directly by logic gates based on opcode bits and status flags. Like a digital circuit — state machine with flipflops and gates. Fast but inflexible.

Microprogrammed CU: Stores control signals as microinstructions in a control memory (ROM). Each machine instruction → a sequence of microinstructions (microprogram). Flexible but slower due to ROM access time.

📋 Part B — 4 marks (Q5)
Explain serial communication with an example.
Serial communication appeared in Part B in BOTH 2024 (Q6) and 2025 (Q5) — two consecutive years. This is now a confirmed permanent Part B fixture. Cover synchronous vs asynchronous, start/stop bits, baud rate.
HIGH confidence

Serial communication transmits data one bit at a time over a single wire (one bit per clock cycle). It is slower than parallel but uses fewer wires and is used for long-distance communication (USB, RS-232, I²C, SPI).

Asynchronous Serial Transmission: No shared clock between sender and receiver. Each character framed by start bit (0) and stop bit(s) (1). Receiver synchronises on start bit edge.

Asynchronous Frame Format (8-bit data, 1 stop bit)
| START | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | STOP |
| 0 | ← 8 data bits (LSB first) → | 1 |
Total frame = 10 bits for 8 data bits | Overhead = 2 bits (20%)

Example from 2023-Aug paper: A 1200-baud line transmits asynchronous with 1 stop bit:

  • Frame = 1 start + 8 data + 1 stop = 10 bits
  • Characters per second = 1200 / 10 = 120 characters/second
  • With 2 stop bits: frame = 11 bits → 1200/11 ≈ 109 characters/second
  • Synchronous (no start/stop): frame = 8 bits → 1200/8 = 150 characters/second

Baud rate = number of signal changes per second. For binary: 1 baud = 1 bit/second.

📋 Part B — 4 marks (Q6)
Explain the need of cache memory. Also explain Hit Ratio.
Cache memory + Hit Ratio as a Part B question appeared in 2025 Part B Q6. The 2022 paper treated it in Part C. 2026 will test it in Part B again. Cover temporal/spatial locality, hit time, miss penalty.
HIGH confidence

Need of Cache Memory: Main memory (DRAM) is 10–100x slower than the CPU. Without cache, the CPU would wait idle for memory. Cache exploits two key principles:

  • Temporal Locality: Recently accessed data is likely to be accessed again soon (e.g., loop variables)
  • Spatial Locality: Data near recently accessed data is likely to be accessed soon (e.g., array elements)
Hit Ratio and Average Access Time
H = Cache Hit Ratio = Cache hits / Total accesses
T_avg = H × Tc + (1−H) × Tm [simultaneous access model]
T_avg = H × Tc + (1−H) × (Tc + Tm) [sequential access model]
Tc = Cache access time | Tm = Main memory access time | H typically 0.8–0.99

Numerical Example: Tc = 5ns, Tm = 50ns, H = 0.9

  • Simultaneous: T_avg = 0.9×5 + 0.1×50 = 4.5 + 5 = 9.5 ns
  • Sequential: T_avg = 0.9×5 + 0.1×(5+50) = 4.5 + 5.5 = 10 ns
📋 Part B — 4 marks (Q7)
Explain arithmetic pipeline with an example.
Arithmetic pipeline appeared in 2024 Part B Q7 and was absent in 2025. Integer division appeared in 2025 Q7. For 2026, arithmetic pipeline is more likely given its one-year absence. Prepare a 4-stage floating-point adder pipeline.
MEDIUM-HIGH confidence

An arithmetic pipeline is a pipeline specifically designed to perform arithmetic operations (addition, multiplication) on floating-point numbers in stages. Each stage performs part of the computation, and results flow through stages one clock cycle at a time.

4-Stage Floating-Point Adder Pipeline:

  • Stage 1 — Compare exponents: Subtract exponents: e1 − e2
  • Stage 2 — Align mantissa: Shift mantissa of smaller number right by |e1−e2| bits
  • Stage 3 — Add mantissas: Add aligned mantissas
  • Stage 4 — Normalise result: Adjust result to normalised floating-point form
Pipeline Speedup Example — 100 additions
Without pipeline: 100 × 4 = 400 clock cycles
With 4-stage pipeline: 4 + (100−1) = 103 clock cycles
Speedup = 400 / 103 ≈ 3.88× faster
Formula: Time = k + (n−1) clock cycles | k = stages | n = number of tasks

📖 Part C — 10 marks (Q2)
What is DMA? Draw the block diagram of DMA controller and explain it.
DMA appeared as Part C Q1 in 2024 and Part C Q4 in 2025 — two consecutive papers. This is the most consistently tested Part C topic alongside Booth's. CERTAIN for 2026. Draw the full DMA controller diagram.
CERTAIN

DMA (Direct Memory Access) is an I/O technique that allows I/O devices to transfer data directly to/from main memory without CPU involvement for each data word. The CPU only sets up the DMA transfer — then the DMA controller handles the actual byte-by-byte transfer, freeing the CPU for other tasks.

Why DMA? Programmed I/O wastes CPU time waiting for I/O; interrupt-driven I/O still requires CPU for each word transfer. DMA handles entire blocks of data autonomously.

Fig — DMA Controller Block Diagram: CPU sets up registers; DMA autonomously transfers data between I/O device and main memory

DMA Operation Steps:

  • Step 1 — CPU Setup: CPU initialises DMA: loads starting memory address into MAR, word count into WC, direction (read/write) into Control Register. CPU then frees itself.
  • Step 2 — DMA Request: I/O device signals DMA when ready to transfer. DMA requests bus control from CPU (HOLD/HLDA signals).
  • Step 3 — Cycle Stealing: DMA steals one bus cycle at a time — CPU releases bus briefly, DMA transfers one word, returns bus to CPU. CPU continues with non-memory operations.
  • Step 4 — Count Down: DMA decrements WC after each word transfer, increments MAR to next memory location.
  • Step 5 — Completion Interrupt: When WC reaches 0, DMA signals CPU via interrupt. CPU resumes I/O control.
📖 Part C — 10 marks (Q3)
Explain Booth's Algorithm with flowchart. Perform multiplication of (-11) × (+6) using Booth's Algorithm.
Booth's Algorithm has appeared in EVERY SINGLE CAO paper: 2022 (-13×+9), 2024 (8×-8), 2025 (-13×+9). New values will be used in 2026 — do NOT memorise one example. Master the flowchart and the step-by-step register method for any pair of signed numbers.
CERTAIN — 100% of all papers

Booth's Algorithm is a hardware multiplication algorithm for signed (2's complement) binary numbers. It produces the correct 2n-bit product for two n-bit signed operands by examining pairs of multiplier bits and deciding whether to add, subtract, or do nothing to an accumulator.

Booth's Algorithm — Rules for Each Step
Examine (Qₙ, Qₙ₋₁) — current bit and previous bit of multiplier Q
00 → Arithmetic Shift Right (ASR) only — no add/subtract
01 → A ← A + M ; then ASR(A, Q, Qₙ₋₁)
10 → A ← A − M ; then ASR(A, Q, Qₙ₋₁) [subtract = add 2's complement]
11 → Arithmetic Shift Right (ASR) only — no add/subtract
Initial: A=0, Q=multiplier, Q₋₁=0, M=multiplicand | Repeat n times | Result in (A,Q)

Worked Example: (-11) × (+6), using 5-bit representation

  • (-11) in 5-bit 2's complement: 10101 = Multiplicand M
  • (+6) in 5-bit: 00110 = Multiplier Q, initially Q₋₁ = 0
  • -M (for subtraction) = 01011
Booth's Steps — (-11) × (+6), n=5 iterations
Init: A=00000 Q=00110 Q₋₁=0 M=10101 -M=01011
─────────────────────────────────────────────────
Step 1: Q₁Q₋₁ = Q₀,Q₋₁ = 0,0 → ASR
A=00000 Q=00011 Q₋₁=0
Step 2: Q₀Q₋₁ = 1,0 → A ← A+M = 00000+10101 = 10101
ASR: A=11010 Q=10001 Q₋₁=1
Step 3: Q₀Q₋₁ = 1,1 → ASR only
A=11101 Q=01000 Q₋₁=1
Step 4: Q₀Q₋₁ = 0,1 → A ← A-M = A+(-M) = 11101+01011 = 101000 → 01000
ASR: A=00100 Q=00100 Q₋₁=0
Step 5: Q₀Q₋₁ = 0,0 → ASR only
A=00010 Q=00010 Q₋₁=0
─────────────────────────────────────────────────
Result = (A,Q) = 00010 00010 = 0001000010 binary
Decimal check: -11 × +6 = -66 ✓ (0001000010 = -66 in signed)
⚡

Booth's Exam Trick: Always verify: convert your final binary result to decimal and check it equals multiplicand × multiplier. For (-11)×(+6) = -66 in decimal. If your binary answer in (A,Q) = -66, you are correct. Also: arithmetic shift right preserves the sign bit (replicate MSB), unlike logical shift right which fills with 0.

📖 Part C — 10 marks (Q4)
Explain the need of cache memory. Elaborate over the three types of mapping with neat diagrams.
All three cache mapping types in one Part C question appeared in 2022 (Q3) — absent from 2023, 2024, 2025. A three-year absence makes this strongly overdue. The 2026 DIP paper brought back 2022-only topics. Cover all 3: direct, associative, set-associative with worked examples.
HIGH confidence

Need of Cache Memory: CPU speed grows faster than DRAM speed — the "memory wall" problem. Cache bridges this gap using temporal and spatial locality.

Three Cache Mapping Techniques:

1. Direct Mapping: Each main memory block maps to exactly ONE cache line. Simple and fast lookup, but suffers from conflict misses.

Address = Tag | Line Number | Word Offset
Cache Line = Block number mod (Number of cache lines)
Hit check: compare address tag with stored tag at that line. If match → hit, else → miss + replace

2. Fully Associative Mapping: Any main memory block can go into any cache line. Maximum flexibility, minimum conflict misses, but expensive comparison hardware (one comparator per line).

Address = Tag | Word Offset
Hit check: Compare tag against ALL cache lines simultaneously (parallel comparison)
Replacement: LRU (Least Recently Used), FIFO, or Random

3. Set-Associative Mapping: Compromise. Cache divided into s sets, each with k lines. Block maps to one set (direct) but any line within that set (associative). k-way set associative.

Address = Tag | Set Number | Word Offset
Set = Block number mod (Number of sets)
Hit check: Check all k lines in the selected set (only k comparators needed) | Most used: 2-way, 4-way, 8-way

Comparison Table:

Property | Direct | Associative | Set-Assoc
────────────────────────────────────────────────────
Flexibility | Lowest | Highest | Middle
Conflict misses | High | None | Low
Hardware cost | Lowest | Highest | Middle
Search time | Fastest | Slowest | Fast
Usage | Simple caches| TLBs | Modern CPUs
📖 Part C — 10 marks (Q5)
How many 128×8 RAM chips are needed for a memory capacity of 4096 bytes? (+ address lines, chip select lines, decoder size)
The 128×8 RAM chip design problem appeared in 2022 (Part C Q5, for 2048 bytes) and 2025 (Part C Q5, for 2048 bytes). For 2026, the memory size will change — predicted: 4096 bytes. The METHOD is identical — master it for any given size.
HIGH confidence

Given: RAM chip size = 128 × 8 bits. Target memory = 4096 bytes.

RAM Chip Design — Step by Step (MEMORISE THIS METHOD)
Chip capacity = 128 × 8 = 128 bytes (128 words, 8 bits each)
─────────────────────────────────────────────────
(i) Number of chips = Total memory / Chip size
= 4096 / 128 = 32 chips
─────────────────────────────────────────────────
(ii) Address bus lines = log₂(Total words) = log₂(4096) = 12 lines
Chip address lines = log₂(128) = 7 lines (common to ALL chips)
Chip select lines = 12 − 7 = 5 lines
─────────────────────────────────────────────────
(iii) Chip select lines needed for decoder = 5 lines
─────────────────────────────────────────────────
(iv) Decoder size = 5 × 32 (5-to-32 decoder)
(5 input lines select 1 of 32 chips)
Verify: 32 chips × 128 bytes = 4096 bytes ✓ | 2^5 = 32 chips ✓ | 7+5=12 address lines ✓
⚡

Quick Formula for any RAM chip problem:
Chips = Target / Chip_size
Total address bits = log₂(Target words)
Chip address bits = log₂(Chip words)
Chip select bits = Total − Chip = log₂(Number of chips)
Decoder = (chip select bits) × (Number of chips)
