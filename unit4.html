General Register Organization

80%

What is General Register Organization?

In a General Register Organization (GRO), the CPU has multiple general-purpose registers (GPRs) — typically 8, 16, or 32 — that can hold both data and addresses. Unlike the basic computer's single accumulator, any register can serve as source or destination. This is the architecture used by all modern processors (x86, ARM, MIPS).

In the basic computer, you have only ONE work area (the accumulator). In a general register organization, you have a whole row of workbenches (registers) — any of them can hold your work, and you can pick any combination for operations. More registers = fewer memory accesses = faster programs.
General Register CPU — Instruction Format
3-address: OP R1, R2, R3 → R1 ← R2 op R3 (all three specified)
2-address: OP R1, R2 → R1 ← R1 op R2 (R1 is both source and destination)
1-address: OP R1 → AC ← AC op R1 (one explicit, one implicit = AC)
0-address: OP → stack-based: pop two, operate, push result
RTU PYQ 2023-Aug: "Write program for X = (A-B+C*(D*E-F))/(G+H*K) using all four address types"

Internal Organization of a Register File

A register file with n registers is connected to the ALU via buses. The CPU typically has:

  • MUX A: Selects one register to put on Bus A (first ALU input)
  • MUX B: Selects one register to put on Bus B (second ALU input)
  • Decoder: Selects which register receives the ALU result (Bus C)
Control Word for Register Operations
Control word fields: | SELA (src1) | SELB (src2) | SELD (dest) | ALU-op |
Example: R3 ← R1 + R2 → SELA=01, SELB=10, SELD=11, ALU-op=ADD
All registers are simultaneously readable (via MUX) — only one write per cycle (via decoder)

Condition Code Register (Status Register / Flags)

Most CPUs have a special register storing condition flags set by ALU operations:

Stack Organization

82%

What is Stack Organization?

A stack is a Last-In-First-Out (LIFO) data structure where items are added and removed from only one end (the top). In CPUs, the stack is used for subroutine calls, interrupt handling, and expression evaluation. The Stack Pointer (SP) register always points to the top of the stack.

A stack is like a pile of plates. You can only put a new plate ON TOP (push) and only take the TOP plate OFF (pop). The last plate you put on is the first one you take off — Last In, First Out. CPUs use this for saving state during function calls: push your current work on the pile before going to a function, pop it back when you return.
Stack Operations — PUSH and POP
PUSH X: SP ← SP + 1 (increment stack pointer first — grows upward)
M[SP] ← X (store X at new top of stack)
POP X: X ← M[SP] (read from top of stack)
SP ← SP - 1 (decrement stack pointer)
Note: Some architectures grow downward (SP decrements on push). RTU basic computer: SP increments on push (grows upward). Always state your assumption!

Stack Applications — RTU Exam Focus

1. Reverse Polish Notation (Postfix) Evaluation

Reverse Polish Notation (RPN) or postfix notation places operators AFTER operands. It eliminates the need for parentheses and is naturally evaluated using a stack. This is how stack-organized computers (0-address computers) work.

Postfix Evaluation using Stack
Infix: A + B * C → Postfix: A B C * +
Infix: (A + B) * C → Postfix: A B + C *
Infix: A * B + C * D → Postfix: A B * C D * +
Algorithm: Scan left to right:
If OPERAND → PUSH onto stack
If OPERATOR → POP two operands, apply operator, PUSH result
Final answer is at top of stack
Example: A B C * + : Push A, Push B, Push C; Pop C,B → B*C → Push; Pop (B*C),A → A+(B*C) → Push → Done
⚡
Infix to Postfix Conversion Trick

Use operator precedence: * and / before + and -. For same precedence, left-to-right. Steps: (1) Add full parentheses according to precedence. (2) Move each operator to replace its RIGHT parenthesis. (3) Remove all parentheses.
Example: A+B*C → A+(B*C) → A+(BC*) → ABC*+

What is an Instruction Format?

An instruction format defines the layout of bits in a machine instruction — which bits encode the operation (opcode), which encode operand addresses, and which encode addressing mode information. The format determines how many operations can be specified, how many operands, and how much memory can be addressed.

Instruction format is the form design for giving orders to the CPU. Like a form with fields: "What to do?" (opcode field), "Where is the first data?" (address field 1), "Where is the second data?" (address field 2). Different computers use different form designs — some have 3 address fields, some have 0.

Four Types of Instruction Formats (Number of Address Fields)

Address Types — Format and RTL
3-Address: OP R1, R2, R3 R1 ← R2 op R3 (all three explicit)
2-Address: OP R1, R2 R1 ← R1 op R2 (R1 = source AND destination)
1-Address: OP R1 AC ← AC op R1 (implicit accumulator)
0-Address: OP TOS ← TOS op TOS-1 (stack-based)

Trade-offs in Instruction Format Design

📝 RTU PYQs — Instruction Format
Q. What are the most common fields of an Instruction format?
2025 Part A Q2 · 2 marks ⭐⭐⭐Instruction Format🔮 HIGH 2026 Part A
The most common fields in an instruction format are:

1. Opcode Field: Specifies the operation to be performed (ADD, SUB, LOAD, STORE, BRANCH). Width determines how many distinct operations are possible: k-bit opcode → 2^k operations.

2. Address Field(s): Specify the location of operands (register numbers or memory addresses). Number varies: 3-address (two sources + destination), 2-address, 1-address, or 0-address.

3. Mode Field: Specifies the addressing mode (how the address field is interpreted — immediate, direct, indirect, register, indexed, etc.).

Optional fields: Condition code (for conditional branches), immediate data (for immediate addressing mode), displacement/offset (for indexed/relative addressing).

The total instruction width = opcode bits + mode bits + address bits. Must fit in one memory word (16, 32, or 64 bits).

🔮

What are Addressing Modes?

Addressing modes specify how the CPU computes the Effective Address (EA) of an operand from the address field in the instruction. Different modes provide different trade-offs between flexibility, speed, and code size.

Addressing mode is the method of finding what you're looking for. If a friend says "meet me at 42 Main Street" — that's direct addressing (the address IS the destination). If they say "meet me where the blue car is parked (and the car is at 42 Main)" — that's indirect (the address points to another address). "Meet me 3 streets from here" — that's relative.
All Addressing Modes — EA Computation
1. Implied (Inherent): EA = operand is implied (e.g., CLA — accumulator is implied)
2. Immediate: Operand = address field itself (EA has no meaning — VALUE is in instruction)
ADD #5 → AC ← AC + 5 (# means immediate)
3. Direct (Absolute): EA = address field → operand = M[EA]
ADD 500 → AC ← AC + M[500]
4. Indirect: EA = M[address field] → operand = M[M[addr]]
ADD (500) → EA = M[500], operand = M[M[500]]
5. Register: EA = register number → operand = R[n]
ADD R3 → AC ← AC + R3
6. Register Indirect: EA = content of register → operand = M[R[n]]
ADD (R3) → AC ← AC + M[R3] (R3 holds the address)
7. Relative: EA = PC + displacement
BUN +5 → PC ← PC + 5 (jump forward 5 from current PC)
8. Indexed: EA = base register + index register
ADD X(R1) → EA = X + R1 (X = base address, R1 = array index)
9. Base Register: EA = base register + displacement (like indexed but fixed base)

Immediate: 0 extra accesses (value IN the instruction)
Register: 0 memory accesses (value in CPU register)
Direct: 1 memory access (to get the operand)

📝 RTU PYQs — Addressing Modes
Q. What is immediate addressing mode?
2025 Part A Q3 · 2 marks ⭐⭐⭐Addressing Mode🔮 HIGH 2026 Part A
In immediate addressing mode, the operand is specified DIRECTLY in the instruction itself — the address field of the instruction contains the actual data value (not an address).

Key features:
• No memory access needed to get the operand → fastest addressing mode
• The operand is called an "immediate value" or "literal"
• Limited range: operand size is limited by the width of the address field

Examples:
ADD #5 — Add the constant 5 to the accumulator (AC ← AC + 5)
MOV R1, #100 — Load the value 100 into register R1

Use cases: Loading constants, initializing registers, loop counter initialization (like loading -N into a counter register for an N-iteration loop).
Q. How many times does the control unit refer to memory when it fetches and executes an indirect addressing mode instruction if the instruction is (a) a computational type requiring an operand from memory, (b) a branch type?
2023-Aug Part B Q6 · 8 marks ⭐⭐Indirect Addressing
For an indirect addressing mode instruction, memory accesses occur in each phase:

(a) Computational Instruction (e.g., ADD I X):
Phase 1 — Fetch: AR ← PC; IR ← M[AR]; PC ← PC+1 → 1 memory read
Phase 2 — Indirect Cycle (I=1): AR ← M[AR] → reads the pointer → 1 memory read
Phase 3 — Execute: DR ← M[AR] (read operand), then AC ← AC + DR → 1 memory read
Total: 3 memory references

(b) Branch Instruction (e.g., BUN I X):
Phase 1 — Fetch: IR ← M[AR]; PC ← PC+1 → 1 memory read
Phase 2 — Indirect Cycle: AR ← M[AR] → reads the pointer → 1 memory read
Phase 3 — Execute: PC ← AR (just updates PC — no memory read for a branch!) → 0 memory reads
Total: 2 memory references

Summary: Indirect + Computational = 3 refs | Indirect + Branch = 2 refs.

What is RISC?

RISC (Reduced Instruction Set Computer) is a CPU design philosophy that uses a small, highly optimized set of simple instructions, each executing in a single clock cycle. RISC processors are optimized for speed through hardware simplicity and compiler sophistication.

RISC is like a fast-food restaurant with only 5 items on the menu — each item is prepared in exactly the same time (1 clock cycle) using simple, standardized cooking steps. You may need to order more items to get a full meal, but everything is fast and predictable. CISC (the alternative) is like a restaurant with 500 items where some dishes take 20 steps to prepare and take much longer.

Key Characteristics of RISC

  1. Simple instructions: Small instruction set — typically 50–150 instructions (vs 200–300+ for CISC)
  2. Single clock cycle execution: Most instructions complete in exactly one clock cycle
  3. Load/Store architecture: Only LOAD and STORE instructions access memory; all other instructions operate on registers only
  4. Fixed-length instructions: All instructions are the same width (e.g., 32 bits) — simplifies fetch and decode
  5. Large number of registers: RISC I has 138 registers in a register window scheme (vs 8–16 in typical CISC)
  6. Hardwired control: Control unit is hardwired (not microprogrammed) → faster
  7. Pipelining: Simple instructions make deep pipelining straightforward
  8. Compiler-based optimization: Compiler does complex work that CISC hardware does (compiler calculates which registers to use, instruction scheduling)
  9. Few addressing modes: Typically only register and register-with-offset
  10. No condition codes (some RISC): Condition results stored in registers, not flags

What is Flynn's Taxonomy?

Flynn's taxonomy (proposed by Michael J. Flynn, 1966) classifies computer architectures based on the number of concurrent Instruction Streams (IS) and Data Streams (DS). Two possible values each (Single or Multiple) give four combinations.

Flynn classified computers by asking two questions: (1) How many different instruction sequences run at once? (2) How many different data sets are processed at once? One instruction, one data = the normal computer you know. Multiple instructions, multiple data = modern multiprocessor. The four combinations cover every type of parallel computer.
Flynn's Classification — 2×2 Matrix
| Single Data Stream | Multiple Data Streams
Single IS | SISD | SIMD
Multiple IS| MISD | MIMD

SISD — Single Instruction, Single Data

One instruction stream processes one data stream at a time. This is the conventional von Neumann architecture — a single CPU executing one instruction on one data at a time.

SISD
IS: 1 instruction sequence | DS: 1 data stream | PU: 1 processing unit
Examples: Single-core processor, basic computer, Intel 8086
Performance improvement possible through pipelining (but still SISD — one instruction at a time from programmer's view)

SIMD — Single Instruction, Multiple Data

One instruction stream is broadcast to MULTIPLE processing elements, each operating on DIFFERENT data simultaneously. All PEs execute the SAME instruction but on different parts of the dataset.

SIMD
IS: 1 instruction (broadcast to all PEs) | DS: Multiple data streams | PU: n processing units
Examples: GPU (NVIDIA CUDA), vector processors, Intel SSE/AVX, MMX
Ideal for: Image processing (same filter on every pixel), scientific computing, machine learning (matrix operations)
All PEs are synchronized — if one finishes early, it waits for others. Efficient only when SAME operation on DIFFERENT data.

MISD — Multiple Instructions, Single Data

Multiple processing units execute DIFFERENT instructions on the SAME data stream simultaneously. Rarely implemented in practice (mostly theoretical). Fault-tolerant systems use it for redundancy checking.

MISD
IS: Multiple instruction streams | DS: 1 data stream | PU: n processing units
Theoretical examples: Systolic arrays, pipeline processors (sometimes classified here)
Practically uncommon — no real commercial system fits this cleanly. Used in fault-tolerant designs where multiple algorithms check the same data for errors.

MIMD — Multiple Instructions, Multiple Data

Multiple autonomous processors execute DIFFERENT instructions on DIFFERENT data independently. This is the most general and most common parallel computer architecture.

MIMD
IS: Multiple different instruction streams | DS: Multiple different data streams | PU: n independent processors
Examples: Shared-memory multiprocessors, distributed systems, computer clusters, multi-core CPUs
Types: Shared memory MIMD (UMA/NUMA) vs Distributed memory MIMD (clusters, MPP)
Intel Core i9 (8 cores) = MIMD: each core runs different programs on different data independently

Parallel Processing:
Parallel processing is the simultaneous use of multiple computational resources to solve a problem faster. Instead of one processor executing instructions sequentially, multiple processors work concurrently on different parts of the problem.

Flynn's Classification:
Michael Flynn (1966) classified computer architectures based on the number of Instruction Streams (IS) and Data Streams (DS).

1. SISD (Single Instruction, Single Data):
One control unit, one processor, one data stream. Sequential von Neumann architecture. One instruction acts on one data at a time. Example: Intel 8086, basic computer.

2. SIMD (Single Instruction, Multiple Data):
One instruction is broadcast to multiple processing elements simultaneously, each operating on different data. All PEs execute same instruction synchronously. Example: GPU, vector processor, Intel SSE. Use: Image processing, scientific computing.

3. MISD (Multiple Instructions, Single Data):
Multiple processors execute different instructions on the same data. Theoretical/rarely implemented. Example: Fault-tolerant systems where same data is verified by different algorithms.

4. MIMD (Multiple Instructions, Multiple Data):
Multiple independent processors each execute different instruction sequences on different data. Most versatile and common parallel architecture. Example: Multicore CPUs, computer clusters, supercomputers.

Key aspects:

Multiprocessor vs Multicomputer

Multiprocessor: Multiple processors share a common memory (shared-memory system). All CPUs can access any memory location. Fast communication but memory contention is a bottleneck.

Multicomputer: Each processor has its own private memory (distributed-memory system). Communication via message passing. Scales better but communication overhead is higher.

Amdahl's Law — Speedup with Parallelism
S = 1 / (f + (1-f)/n)
where: f = fraction of program that CANNOT be parallelized (serial fraction)
n = number of processors
S = speedup factor
(1-f) = fraction that CAN be parallelized
Example: f = 0.1 (10% serial), n = 8 processors:
S = 1 / (0.1 + 0.9/8) = 1 / (0.1 + 0.1125) = 1/0.2125 ≈ 4.7 (not 8!)
Key insight: Even with infinite processors, speedup is limited to 1/f. If 20% is serial, max speedup = 5×.

What is Pipelining?

Pipelining is a technique of implementing parallel computing within a single processor. It overlaps the execution of multiple instructions simultaneously by dividing the execution process into distinct stages. Like a factory assembly line — multiple products (instructions) are at different stages of production simultaneously.

Imagine washing dishes: wash → rinse → dry → put away. Without pipeline: finish ALL 4 steps for dish 1 before starting dish 2. WITH pipeline: while you dry dish 1, you can rinse dish 2 AND wash dish 3 simultaneously. The dishes form a "pipeline" — different dishes at different stages at the same time. 4x faster if all 4 stages are always busy.

Pipeline Performance Metrics — RTU Exam Formulas ⭐⭐⭐

Pipeline Formulas — Essential for Numericals
Definitions:
k = number of pipeline stages
n = number of tasks to process
t = clock cycle time (time for one stage = time of longest stage)
Time WITHOUT pipeline (non-pipelined): Tₙ = n × k × t (each task takes k stages)
Time WITH pipeline: Tₚ = (k + n - 1) × t (k to fill + n-1 more)
Speedup: S = Tₙ / Tₚ = (n×k×t) / ((k + n - 1)×t) = n×k / (k + n - 1)
For large n: S ≈ k (approaches number of stages)
Throughput: Tput = n / Tₚ = n / ((k + n - 1)×t) [tasks per unit time]
Max throughput (large n): Tput_max = 1/t [one task per clock cycle]
Efficiency: E = S / k = n / (k + n - 1) [fraction of time stages are busy]
RTU 2022: non-pipeline = 100 ns/task; pipeline 6-stage, 20 ns clock, 200 tasks
→ Tₙ = 200×100 = 20,000 ns | Tₚ = (6+200-1)×20 = 205×20 = 4,100 ns
→ Speedup = 20,000/4,100 ≈ 4.88 | Max speedup = 6 (approached as n→∞)

Pipeline Characteristics — RTU Part A Q4 (2025)

  1. Overlap: Multiple instructions are in different stages simultaneously — the defining feature
  2. Throughput: Rate at which tasks complete = approximately 1 task per clock cycle for large n
  3. Latency: Time to complete ONE task = k × t (still takes all k stages)
  4. Speedup approaches k: For n >> k, speedup → k (number of stages)
  5. All stages must take equal time: Slowest stage sets the clock period
  6. Hazards: Structural hazards (resource conflict), data hazards (RAW/WAR/WAW dependencies), control hazards (branches)

Q. A non-pipeline system takes 100 ns to process a task. The same task can be processed in a six-segment pipeline with a clock cycle of 20 ns. Determine the speed-up ratio for 200 tasks. What is maximum speed-up that can be achieved?
2022 Part B Q3 · 8 marks ⭐⭐⭐Pipeline Speedup🔮 HIGH 2026 Part B
Given: Non-pipelined: 100 ns/task | Pipeline: k=6 stages, t=20 ns/stage, n=200 tasks

Non-pipelined time (Tₙ):
Tₙ = n × (time per task) = 200 × 100 = 20,000 ns
(Alternatively: n × k × t = 200 × 6 × 20 = 24,000 ns if using stage time)
Note: Given 100 ns/task directly → use 200 × 100 = 20,000 ns

Pipelined time (Tₚ):
Tₚ = (k + n − 1) × t = (6 + 200 − 1) × 20 = 205 × 20 = 4,100 ns

Speedup:
S = Tₙ / Tₚ = 20,000 / 4,100 = 4.88 ≈ 4.9

Maximum Speedup (n → ∞):
As n becomes very large: S_max → k = 6
Derivation: S = nk/(k+n-1). Divide by n: S = k/(k/n + 1 - 1/n). As n→∞: S → k/(0+1-0) = k.

Conclusion: With 200 tasks, speedup = 4.88. Maximum possible speedup = 6 (equal to number of stages, achieved as n approaches infinity).
Q. What are the major characteristics of a pipeline?
2025 Part A Q4 · 2 marks ⭐⭐⭐Pipeline Characteristics🔮 HIGH 2026 Part A
Major characteristics of a pipeline:

1. Overlap/Concurrency: Multiple instructions are in different stages simultaneously — this is what creates the speedup.
2. Throughput: A task completes every clock cycle (for large n). Maximum throughput = 1/t (one task per clock period).
3. Latency: Time to complete ONE task = k × t. Pipelining does NOT reduce single-task latency, only increases throughput.
4. Clock cycle = slowest stage: The clock period is determined by the longest pipeline stage. Stages must be balanced.
5. Speedup approaches k: For large number of tasks (n >> k), speedup → k (number of stages).
6. Efficiency: E = S/k (fraction of time all stages are active). For large n, efficiency → 1 (100%).
7. Hazards: Data hazards (RAW dependencies), control hazards (branches), and structural hazards (resource conflicts) reduce effective speedup.

Arithmetic Pipeline

🔥 85% — Part B 2024

What is an Arithmetic Pipeline?

An arithmetic pipeline divides a complex arithmetic operation (like floating-point addition) into sub-operations, each assigned to a separate pipeline stage. Different sets of operands flow through the pipeline, with each stage processing its portion simultaneously.

An arithmetic pipeline is like a specialized factory for computing one type of operation (like floating-point addition). The factory has 4 stations: normalize numbers, align exponents, add mantissas, normalize result. While Station 4 finishes adding A+B, Station 3 can already be adding C+D, and Station 2 can be aligning E+F's exponents. All happening simultaneously!

Floating-Point Addition Pipeline (4 Stages) — RTU Exam Example

Floating-point addition requires 4 steps, each implemented as a pipeline stage:

1
Compare Exponents: Subtract exponents to find the difference. EA - EB = shift amount. (Determines how many positions to shift the smaller mantissa)
2
Align Mantissas: Right-shift the mantissa of the number with the smaller exponent by the amount found in Stage 1. Both mantissas now have the same exponent.
3
Add/Subtract Mantissas: Perform the actual addition or subtraction of the aligned mantissas. Result mantissa may be unnormalized.
4
Normalize Result: Adjust the result mantissa (shift left until leading 1, adjusting exponent accordingly). Store sign, exponent, mantissa.
Fig 11.1 — 4-Stage Floating-Point Adder Pipeline: Compare Exponents → Align → Add → Normalize. Latches between stages hold intermediate results.

Arithmetic Pipeline:
An arithmetic pipeline divides a complex arithmetic operation into sequential sub-operations implemented as pipeline stages. Different operand pairs are at different stages simultaneously, increasing throughput.

Example — Floating-Point Addition Pipeline (4 stages):

Stage 1 — Compare Exponents: EA − EB = d (determine shift amount)
Stage 2 — Align Mantissas: shift smaller mantissa right by d positions
Stage 3 — Add Mantissas: perform binary addition of aligned mantissas
Stage 4 — Normalize Result: adjust mantissa so leading bit is 1; update exponent

Pipeline timing for 3 additions:
Clock 1: A1+B1 in Stage 1
Clock 2: A1+B1 in Stage 2 | A2+B2 in Stage 1
Clock 3: A1+B1 in Stage 3 | A2+B2 in Stage 2 | A3+B3 in Stage 1
Clock 4: A1+B1 in Stage 4 | A2+B2 in Stage 3 | A3+B3 in Stage 2
Clock 5: Result1 out | A2+B2 in Stage 4 | A3+B3 in Stage 3
Clock 6: Result2 out | A3+B3 in Stage 4
Clock 7: Result3 out

Advantage: Without pipeline: 3 × 4 = 12 clock cycles. With pipeline: 4 + 3 - 1 = 6 clock cycles. Speedup ≈ 2×.

Instruction Pipeline (6-Segment)

🔥 88% — Part C 2022

What is an Instruction Pipeline?

An instruction pipeline overlaps the execution of multiple machine instructions simultaneously by dividing instruction processing into stages. The classic 6-stage instruction pipeline processes one instruction per clock cycle at steady state.

6-Stage Instruction Pipeline

StageNameAction
S1: FIFetch InstructionRead instruction from memory (or cache) into IR
S2: DIDecode InstructionDetermine opcode, operand addresses, addressing mode
S3: COCalculate Operand AddressCompute effective addresses (EA) for all operands
S4: FOFetch OperandRead operands from memory/registers
S5: EIExecute InstructionPerform ALU operation or other computation
S6: WOWrite OperandStore result in memory or register

Pipeline Hazards — Causes of Stalls

Hazards are situations that prevent the pipeline from executing at maximum throughput:

1. Structural Hazards (Resource Conflicts)

Two instructions need the same hardware resource simultaneously. Example: both S1 (Fetch) and S4 (Fetch Operand) need memory access at the same time.

Solution: Separate instruction cache (I-cache) and data cache (D-cache). Or add more resources (duplicate memory ports).

2. Data Hazards (RAW, WAR, WAW)

An instruction needs data that is being produced by a preceding instruction still in the pipeline.

Types of Data Hazards
RAW (Read After Write): I2 reads R1 before I1 has written R1 ← most common!
WAR (Write After Read): I2 writes R1 before I1 has read R1
WAW (Write After Write): I2 writes R1 before I1 has written R1
Solutions: Pipeline stalls (bubble insertion), data forwarding/bypassing (forward result before writeback), out-of-order execution

3. Control Hazards (Branch Hazards)

When a branch instruction is encountered, the pipeline has already fetched the next sequential instructions, but these may be wrong if the branch is taken.

Solutions: Branch prediction (static or dynamic), delayed branching (execute one instruction after branch regardless), branch target buffer.

⚡
Pipeline Speedup RTU Trick — Steps

For any pipeline speedup question:
1. Find n (number of tasks), k (stages), t (clock period)
2. Non-pipeline time = n × k × t (or n × original_time)
3. Pipeline time = (k + n − 1) × t
4. Speedup = Non-pipeline time / Pipeline time
5. Max speedup (large n) = k
Always show the formula, substitution, and final answer clearly.

Q. Formulate a six-segment instruction pipeline for a computer. Specify the operations to be performed in each segment.
2023-Aug Part C Q4 · 15 marks ⭐⭐⭐Instruction Pipeline🔮 HIGH 2026 Part C
Six-Segment Instruction Pipeline:

A 6-segment instruction pipeline processes one instruction per clock cycle at steady state by dividing instruction execution into 6 overlapping stages:

Segment 1 — FI (Fetch Instruction):
Read the next instruction from memory (or instruction cache) and load it into the instruction register. PC is incremented to point to the next instruction address.

Segment 2 — DI (Decode Instruction):
Decode the instruction to determine: opcode (what operation), type of operands, addressing modes used, and number of operands. Control signals for subsequent stages are generated.

Segment 3 — CO (Calculate Operand Address):
Compute the effective address (EA) for each operand using the addressing mode identified in DI. For register operands, identify register numbers. For memory, compute EA = base + displacement or indirect address resolution.

Segment 4 — FO (Fetch Operands):
Retrieve operand values from memory or registers using the addresses computed in CO. For immediate operands, the value is already available from DI.

Segment 5 — EI (Execute Instruction):
Perform the actual operation: ALU computes arithmetic/logic result, or memory address is finalized for load/store, or branch condition is evaluated.

Segment 6 — WO (Write Operand / Write Back):
Store the result: write to destination register or write to memory. For branches, update PC if branch is taken.

Performance: With k=6 stages and n tasks: Time = (6+n-1)×t. Speedup vs sequential = 6×n/(6+n-1). For large n → speedup approaches 6.

Why Pipeline is Useful:
Modern CPUs operate at GHz speeds, but memory access still takes multiple ns. Without pipelining, the CPU would be idle waiting for each instruction to complete before starting the next. Pipelining keeps the CPU busy all the time by overlapping instruction execution — while one instruction is executing, the next is being decoded, and the one after that is being fetched. This dramatically increases throughput.

[Instruction pipeline explanation — same as the 6-segment answer above]

Performance Metrics:

Let: k = number of stages, n = number of tasks, t = clock period

Throughput: Tput = n / ((k+n-1)×t) → For large n: Tput_max = 1/t

Speedup: S = (n×k×t) / ((k+n-1)×t) = n×k / (k+n-1)

Efficiency: E = S/k = n/(k+n-1) → ranges from 1/(k) [n=1] to 1 [n→∞]

Proof that speedup → k (ratio depends on k):
S = n×k / (k+n-1)
Divide numerator and denominator by n:
S = k / (k/n + 1 - 1/n)
As n → ∞: k/n → 0 and 1/n → 0
Therefore: S → k/(0 + 1 - 0) = k ✓

This proves that the maximum speedup ratio equals the number of pipeline segments k. The pipeline is most efficient when processing a large number of tasks.

RISC Pipeline

Why RISC is Ideal for Pipelining

RISC architectures are specifically designed for efficient pipelining. The characteristics of RISC that make pipelining easy:

  • Fixed-length instructions: All instructions are 32 bits — fetch is always one word, decode is always the same time
  • Load/Store architecture: Memory access only in LOAD/STORE — execution stage only does ALU ops (no memory in EX stage)
  • Simple addressing modes: EA computation is fast and uniform
  • Many registers: Data forwarding is more effective when results stay in registers

Classic RISC 5-Stage Pipeline (MIPS-style)

StageNameAction
IFInstruction FetchFetch instruction from I-cache; PC ← PC+4
ID/RFInstruction Decode / Register FetchDecode instruction; read source registers
EXExecuteALU operation (for R-type) or EA computation (for Load/Store)
MEMMemory AccessData cache read (Load) or write (Store); NOP for R-type
WBWrite BackWrite result to destination register

Delayed Branching in RISC

In RISC pipelines, a branch instruction modifies PC at the EX stage (stage 3), but by then the next instruction (PC+4) has already been fetched in IF. Rather than flush this instruction (waste a cycle), RISC uses delayed branching: the instruction immediately after a branch (the branch delay slot) is ALWAYS executed, regardless of branch outcome. The compiler fills this slot with a useful instruction.

Delayed Branching
Normal code: BEQ R1, R2, TARGET / branch if equal
ADD R3, R4, R5 / this executes BEFORE the branch takes effect
With delayed: ADD R3, R4, R5 / moved here (delay slot) — always executes
BEQ R1, R2, TARGET / branch now jumps
The instruction in the delay slot always executes regardless of branch — compiler must ensure this is safe (not a data dependency conflict)

What is Vector Processing?

A vector processor operates on entire arrays (vectors) of data with a single instruction, rather than processing one element at a time. It uses SIMD-style hardware to apply the same operation to multiple data elements simultaneously.

A vector processor is like a combine harvester vs a person with a sickle. The sickle cuts one stalk at a time (scalar). The combine harvester cuts an entire row in one pass (vector). A single "ADD" instruction adds ALL elements of one array to ALL corresponding elements of another array simultaneously.
Vector vs Scalar Processing
Scalar: for(i=0; i
Vector: C = A + B; ← ONE vector instruction, processes all n elements
Vector instruction fetches entire array A and B → applies ADD to all element pairs → stores result in C
Benefit: Eliminates loop overhead, instruction fetch overhead, and control flow

Vector Processor Design of a RTU Exam Question

A vector processor has:

  • Vector registers: Long registers holding 8, 16, or 64 elements
  • Vector functional units: Pipelined ALUs that process elements in sequence through the pipeline
  • Vector load/store unit: Fetches/stores entire vectors from/to memory
  • Scalar unit: Processes individual scalar values (loop counters, addresses)
📝 RTU PYQs — Vector Processing
Q. Explain the design of a vector processor.
2024 Part C Q4 · 10 marks ⭐⭐Vector Processor
Vector Processor — Introduction:
A vector processor is designed to efficiently execute operations on arrays (vectors) of data using a single instruction. It's classified as SIMD in Flynn's taxonomy.

Key Components:

1. Vector Registers (VR):
Large registers that can hold a vector of elements (e.g., 64 × 64-bit floating-point values). The Cray-1 had 8 vector registers, each holding 64 elements. Vector instructions specify vector register numbers as operands.

2. Vector Functional Units:
Pipelined arithmetic units for vector addition, multiplication, division, logical operations. Each unit is a pipeline — elements enter one per clock cycle, results emerge after the pipeline latency. Multiple functional units can operate simultaneously (chaining).

3. Vector Load/Store Unit:
Transfers entire vectors between vector registers and memory. Can load stride-1 (contiguous) or stride-k (every k-th element) vectors.

4. Scalar Unit:
Standard scalar CPU for non-vector operations — loop control, address calculation, scalar arithmetic.

5. Memory Interleaving:
Memory is organized into multiple independent banks. Different banks can be accessed simultaneously, enabling high-bandwidth vector loads at one element per clock.

Operation Example:
To compute C[i] = A[i] + B[i] for 64 elements:
VLOAD VR1, A (load 64-element vector A)
VLOAD VR2, B (load 64-element vector B)
VADD VR3, VR1, VR2 (add all 64 pairs in pipeline)
VSTORE C, VR3 (store 64-element result)

Advantages: Extremely high throughput for regular, data-parallel applications. Used in weather forecasting, CFD simulation, signal processing.

Array Processors

68%

What are Array Processors?

An array processor (or processor array) is a collection of identical processing elements (PEs) connected in a regular pattern, all operating in lockstep under a single control unit. It is the classic SIMD hardware implementation.

An array processor is like a classroom where the teacher (control unit) says "add your left neighbor's number to your number" and ALL students do it simultaneously. Each student is a PE. The teacher broadcasts one instruction; every student executes it on their own data. Massively parallel for regular patterns.
Array Processor vs Vector Processor
Array Processor: n PEs each with own ALU + local memory, all in sync
One CU broadcasts instructions to all PEs
Physical parallelism — operations literally simultaneous
Vector Processor: One pipelined ALU processes elements sequentially via pipeline
Time-multiplexed parallelism — pipeline stages overlap, not truly simultaneous
Array processor examples: CM-1 Connection Machine (65,536 1-bit PEs), ILLIAC IV, modern GPU compute cores
Key difference: Array = n separate ALUs working truly simultaneously | Vector = 1 pipelined ALU
