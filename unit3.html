Machine Language

80%

What is Machine Language?

Machine language is the lowest-level programming language — the only language a computer's CPU can directly understand and execute. It consists entirely of binary numbers (0s and 1s). Every instruction is a bit pattern that directly maps to a hardware operation.

Machine language is like talking directly to a machine in its own language — pure binary. If you tell the computer "0000 0000 0000 0011" (in the basic computer's format), it knows to do the AND operation on memory address 3. No translation needed — the CPU hardware understands this directly. The problem: extremely hard for humans to write or read!
Machine Language Instruction — Basic Computer Format (16 bits)
Binary: I | Opcode(3) | Address(12)
Example: 0 | 001 | 000000000011 = ADD (direct) memory location 3
1 | 010 | 000000000101 = LDA (indirect) memory location 5
Bit 15 (I): 0 = direct addressing, 1 = indirect addressing
Bits 14-12 (Opcode): 000=AND, 001=ADD, 010=LDA, 011=STA, 100=BUN, 101=BSA, 110=ISZ
Bits 11-0 (Address): 12-bit address → 4096 memory locations

Three Types of Machine Language Instruction Formats

TypeFormatDescriptionExample
Memory-ReferenceI(1) + Opcode(3) + Address(12)Access memory — needs address fieldAND, ADD, LDA, STA, BUN, BSA, ISZ
Register-Reference0111 + Operation(12)Operate on AC — no memory neededCLA, CMA, INC, HLT
I/O Reference1111 + Operation(12)I/O device operationsINP, OUT, SKI, SKO, ION, IOF

Hexadecimal Representation

Machine language is usually written in hexadecimal (base 16) to make it more compact. Each hex digit represents 4 bits. A 16-bit instruction becomes 4 hex digits.

Binary to Hex Conversion for Instructions
Binary: 0 001 000000000011 → 4 groups of 4 bits: 0001 | 0000 | 0000 | 0011
Hex: 1 | 0 | 0 | 3 → 1003 (hex)
Meaning: I=0 (direct), Opcode=001 (ADD), Address=003
Hex 7800: Binary 0111 1000 0000 0000 → Register-reference (opcode=111, I=0)
Bit 11=1 → CLA (Clear Accumulator)
RTU PYQ pattern: Hex addresses are used in instruction cycle problems (2023-Aug C-Q1 used hex 021, 083, B8F2, A937)
📝 RTU PYQs — Machine Language
Q. Describe the three fields (Mode, Opcode and Address field) of 16 bit instruction format.
2022 Part A Q9 · 2 marks ⭐⭐Instruction Format
A 16-bit instruction in the basic computer has three fields:

1. Mode Bit (I) — Bit 15 (1 bit):
Determines the addressing mode. I=0 → Direct addressing (the address field directly gives the operand's memory address). I=1 → Indirect addressing (the address field gives the address of a memory location that CONTAINS the operand's address). Used only for Memory-Reference Instructions.

2. Opcode Field — Bits 14–12 (3 bits):
Specifies which operation to perform. 3 bits → 8 possible operation codes.
000=AND, 001=ADD, 010=LDA, 011=STA, 100=BUN, 101=BSA, 110=ISZ, 111=Non-MRI

3. Address Field — Bits 11–0 (12 bits):
Specifies the memory address of the operand (for MRI) or contains the specific operation code (for Register/I-O reference when opcode=111). 12 bits → 2¹² = 4096 addressable locations.
Q. Specify the instruction format and number of bits in each field if the memory unit has 256K × 32 bit, with instruction format having four fields: opcode, mode (7 addressing modes), register address (60 registers), and memory address, all in one memory word.
2023-Aug Part B Q5 · 8 marks ⭐⭐Instruction Format Design
Given:
Memory: 256K words × 32 bits → address needs log₂(256K) = log₂(2¹⁸) = 18 bits
Word size: 32 bits (instruction must fit in one word)
Fields: opcode + mode + register address + memory address

Field sizes:
Mode field: 7 addressing modes → needs log₂(7) ≈ 3 bits (2³=8 ≥ 7) → 3 bits
Register address: 60 registers → needs log₂(60) ≈ 6 bits (2⁶=64 ≥ 60) → 6 bits
Memory address: 256K = 2¹⁸ locations → 18 bits
Total for mode + register + memory = 3 + 6 + 18 = 27 bits
Remaining for opcode: 32 − 27 = 5 bits (allows 2⁵ = 32 operations)

Final Instruction Format (32 bits):
| Opcode (5) | Mode (3) | Register (6) | Memory Address (18) |

Verification: 5 + 3 + 6 + 18 = 32 bits ✓ (fits in one 32-bit word)

Assembly Language

85%

What is Assembly Language?

Assembly language is a low-level programming language that uses mnemonics (symbolic names) to represent machine language instructions. It is one level above machine language — instead of writing 0001 0000 0000 0011 (binary), you write ADD 3. An assembler then converts this to machine language.

Assembly language is like a cheat sheet for machine language. Instead of remembering that 001 means "ADD," you write "ADD." Instead of 010 for "LDA," you write "LDA." A helper program called the assembler translates your readable shortcuts (mnemonics) back into the binary that the CPU understands. It's still very close to hardware — no automatic memory management, no fancy features — just a thin layer of readability over machine code.
Assembly Language — Basic Computer Mnemonics
Memory-Reference: AND, ADD, LDA, STA, BUN, BSA, ISZ
Register-Reference: CLA, CLE, CMA, CME, CIR, CIL, INC, SPA, SNA, SZA, SZE, HLT
I/O Reference: INP, OUT, SKI, SKO, ION, IOF
Pseudo-Ops: ORG, END, DEC, HEX, BSS, BES
ORG n: Origin — start storing at memory address n
DEC n: Decimal constant — store the decimal value n
HEX n: Hexadecimal constant
END: End of program — assembler stops here

Assembly Language Statement Format

Statement Structure
Label, Instruction/Pseudoinstruction, Comment
LBL, AND X / AND contents of X with AC
X, DEC -23 / Variable X = -23
Label: symbolic name for a memory address (optional). Ends with comma.
Instruction: mnemonic + operand (for MRI) or just mnemonic (for RRI/IOI)
Comment: everything after '/' is ignored by assembler
Indirect addressing: put 'I' after instruction → e.g., "AND I X" means indirect AND with address in X

Q. Differentiate between assembly language and machine language.

Machine Language:
The lowest-level programming language consisting of binary (0s and 1s) instructions that the CPU directly executes. Each instruction is a specific bit pattern that maps to a hardware operation. Example: 0010 000000000011 (binary) or 2003 (hex).

Assembly Language:
A low-level language that uses symbolic mnemonics (meaningful abbreviations) to represent machine language instructions. Requires an assembler to translate to machine code. Example: LDA 3 (equivalent to the above binary).

Assembler — Two-Pass Process

72%

What is an Assembler?

An assembler is a program that translates assembly language source code into machine language (binary/hex) object code. It processes the source file and produces a binary output that the CPU can execute.

The assembler is the translator. It reads your assembly source code (with mnemonics like LDA, ADD, STA) and converts each line into the corresponding binary machine instruction. It also resolves all symbolic labels to actual memory addresses. Think of it as a professional translator who converts your shorthand notes into the machine's native language.

Two-Pass Assembler

A two-pass assembler reads the source file twice. This is necessary because in the first pass, a label defined later in the program (forward reference) is not yet known. The two-pass approach solves this.

1
Pass 1 — Symbol Table Construction: The assembler scans through the entire source code. For every label definition, it records the label name and its corresponding memory address in a Symbol Table. No machine code is generated yet. The Location Counter (LC) tracks the current address and is incremented for each instruction/data.
2
Pass 2 — Code Generation: The assembler scans the source code again. Now it uses the Symbol Table to replace all label references with their actual memory addresses. It converts each mnemonic to its binary opcode and generates the final machine code output.
Assembler Tables Used
Symbol Table: Label | Address (built during Pass 1)
e.g., MIN | 0006 (label MIN is at address 0006)
LOOP | 0002 (label LOOP is at address 0002)
Pseudo-instruction Table: ORG, END, DEC, HEX, BSS
MRI Table: AND→000, ADD→001, LDA→010, STA→011...
Non-MRI Table: CLA→7800, CLE→7400, CMA→7200...

Program Loops

78%

What are Program Loops?

A program loop is a sequence of instructions that repeats a set of operations a fixed number of times. In the basic computer, loops are implemented using the ISZ (Increment and Skip if Zero) instruction as a counter mechanism.

A loop is like counting down from 5 to 0: do the action, subtract 1 from the counter, check if counter is zero — if not, go back and do it again. In the basic computer, ISZ does "increment and check if zero" — so you start with a negative counter (-N) and ISZ counts it UP to zero, at which point it skips the branch instruction and exits the loop.
ISZ — Increment and Skip if Zero
ISZ X: M[X] ← M[X] + 1; if M[X] = 0 then PC ← PC + 1 (skip next instruction)
Loop technique: Initialize counter to -N. Use ISZ to increment. Loop body comes before ISZ. BUN jumps back to start. When counter reaches 0, ISZ skips the BUN → loop exits.

Loop Example — Add N Numbers

Assembly Program — Sum of N Numbers (RTU Exam Pattern) / Program to add N numbers starting at address ADS ORG 100 / Start at address 100 LDA AD / Load base address of array into AC STA PT / Store in pointer PT LDA N / Load N (negative count) into AC STA CTR / Store as counter CLA / Clear AC (will hold sum) LOOP, LDA I PT / Load next number indirectly via pointer ADD SUM / Add to running sum STA SUM / Store updated sum ISZ PT / Increment pointer to next element ISZ CTR / Increment counter; skip next if zero BUN LOOP / If not zero, branch back to LOOP HLT / Halt — sum is in SUM AD, HEX 150 / Starting address of array N, DEC -100 / Negative count (loop 100 times) SUM, DEC 0 / Accumulate sum here PT, DEC 0 / Pointer (changes each iteration) CTR, DEC 0 / Counter copy (changes each iteration) END
⚡
ISZ Loop Trick — Always Use Negative Counter

RTU loop programs always use ISZ with a negative counter. If you want to loop N times, initialize counter to -N. ISZ increments it toward 0. When it reaches 0, it skips the BUN → exits loop. Also remember: ISZ is used for both the counter AND the pointer (to advance through an array). Two ISZ instructions are common in loop programs: one for the counter, one for the pointer.

Programming Arithmetic & Logic Operations

80%

Implementing Arithmetic with Basic Computer Instructions

The basic computer has only ADD as an arithmetic instruction (plus CMA+INC for negation). More complex operations (multiplication, division, subtraction) must be programmed using these primitives.

The basic computer is like having only a few LEGO bricks — just ADD, AND, shift, and complement. But from these few pieces, you can build any arithmetic or logic operation. Subtraction = add the 2's complement. Multiplication = repeated addition. Division = repeated subtraction. This is called programming arithmetic operations.

Subtraction Program

Subtraction: A − B → D (using 2's complement) LDA B / AC ← B CMA / AC ← complement of B (1's complement) INC / AC ← AC + 1 (now AC = 2's complement of B = −B) ADD A / AC ← AC + A = A + (−B) = A − B STA D / D ← A − B HLT A, DEC 85 / First operand B, DEC 23 / Second operand to subtract D, DEC 0 / Result stored here

Multiply Two Numbers (Repeated Addition)

Multiplication: A × B → P (using repeated addition) LDA B / Load B (used as counter) — must be negative CMA / Complement B INC / 2's complement of B (−B as loop counter) STA CTR / CTR = −B (loop B times) CLA / Clear product accumulator STA P / P = 0 initially LOOP, LDA P / Load current partial product ADD A / Add A to partial product STA P / Store updated partial product ISZ CTR / Increment counter; skip if zero BUN LOOP / If not done, repeat HLT / Product P = A × B

Logic Operations in Assembly

Logic operations use the AND instruction combined with complement and manipulation:

Implementing OR: A OR B (since basic computer only has AND) / Use De Morgan's: A OR B = NOT(NOT A AND NOT B) LDA A / AC ← A CMA / AC ← NOT A STA TMP / TMP = NOT A LDA B / AC ← B CMA / AC ← NOT B AND TMP / AC ← NOT A AND NOT B CMA / AC ← NOT(NOT A AND NOT B) = A OR B STA RESULT / Store result

Subroutines

🔥 88% — Part A 2022 & 2025
🔮

What is a Subroutine?

A subroutine (also called a procedure, function, or subprogram) is a self-contained sequence of instructions that performs a specific task and can be called from multiple places in a program. When called, control transfers to the subroutine; when it finishes, control returns to the calling point.

A subroutine is like a reusable recipe. Instead of writing out "boil water" every time you need it, you write it once as a named recipe ("boilWater") and just call it whenever needed. After boiling, the recipe "returns" to where it was called from. In computers, subroutines save memory (code written once, used many times) and make programs organized.

BSA — Branch and Save Address (Subroutine Linkage)

In the basic computer, subroutines are called using the BSA (Branch and Save Address) instruction. BSA saves the return address at the start of the subroutine's memory area and jumps to the instruction after it.

BSA Instruction — RTL Operation
BSA X: M[X] ← PC (save return address at location X)
PC ← X + 1 (jump to first instruction of subroutine at X+1)
After BSA: M[X] holds the return address. PC points to first executable instruction of subroutine.
Return: BUN I SUB (indirect branch to address stored at SUB — this is the saved return address)

Subroutine Example

Calling a Subroutine (BSA) and Returning (BUN I) / Main Program ORG 100 LDA X / Load X into AC BSA SHR / Call subroutine SHR (shifts AC right) / After return, AC holds shifted value STA Y / Store result HLT / --- Subroutine SHR: Shift AC right by 1 --- SHR, HEX 0 / Return address stored here by BSA CIR / Circular shift right BUN I SHR / Return: indirect branch to address saved at SHR
Subroutine Execution Trace
Before BSA: PC = 102 (address of BSA instruction), SHR = 106 (subroutine location)
BSA executes: M[106] ← PC = 103 (save return address 103 at location 106)
PC ← 107 (jump to first instruction of subroutine)
Subroutine executes: CIR (circular right shift)
BUN I SHR: reads M[106] = 103, sets PC ← 103 (returns to calling program)
The key: BSA saves the NEXT address after BSA (the return point), not BSA's own address

Role of the Stack in Subroutine Calls

Modern computers use a stack (Last-In-First-Out data structure) for subroutine linkage instead of BSA. The stack automatically handles nested subroutines and recursion — something BSA alone cannot do (because BSA stores only one return address).

Stack-Based Subroutine Mechanism
CALL instruction: PUSH PC (return address) onto stack, then JUMP to subroutine
RET instruction: POP return address from stack, JUMP to it
SP (Stack Pointer): register pointing to top of stack, auto-decrements on PUSH, increments on POP
Advantage: Stack can hold MANY return addresses (nested calls). Each CALL pushes one, each RET pops one. LIFO order ensures correct unwinding even for deeply nested or recursive calls.
BSA limitation: Only one return address can be saved at location X. If subroutine calls another subroutine, return address is overwritten → cannot nest calls.
⚡
Subroutine Exam Trick — "BSA saves, BUN I returns"

BSA SUB: Branch and Save Address — saves PC at M[SUB], jumps to SUB+1.
BUN I SUB: Indirect Branch — reads M[SUB] (the saved return address) and jumps there.
The pattern is always: BSA at call site, BUN I at end of subroutine. The return address is ALWAYS stored at the FIRST location of the subroutine (label address). Draw this as: [Main] → BSA → [Subroutine starts with return address slot] → [code] → BUN I → [returns to Main].

📝 RTU PYQs — Subroutines
Q. Describe subroutine.
2022 Part A Q3 · 2025 Part A Q9 · 2 marks ⭐⭐⭐Subroutine🔮 VERY HIGH 2026 Part A
A subroutine (also called a procedure or function) is a self-contained group of instructions that performs a specific task and can be called from multiple locations in a program.

Key features:
1. Written once, called multiple times — saves memory and reduces code duplication.
2. When called, the CPU saves the return address (where to return after the subroutine finishes).
3. After completing its task, the subroutine returns control to the calling program.

In the basic computer:
The BSA (Branch and Save Address) instruction implements the subroutine call. BSA saves the return address at the first location of the subroutine and transfers control to the next location. To return, BUN I is used (indirect branch reads the saved return address).

Role of Stack:
Modern processors use a stack (LIFO) to save return addresses. CALL pushes the return address; RET pops it. The stack allows nested and recursive subroutine calls (unlike BSA which can only save one return address per call).
Q. An output program resides in memory starting from address 230. It is executed after the computer recognizes an interrupt when FGO becomes 1 (while IEN=1). (a) What instruction must be placed at address 1? (b) What must be the last two instructions of the output program?
2023-Aug Part B Q4 · 8 marks ⭐⭐I/O + Interrupt
Background: When an interrupt occurs (FGO=1 and IEN=1), the hardware automatically: saves PC at address 0 (M[0] ← PC), sets PC = 1 (jumps to interrupt vector address 1), clears IEN=0 (disables further interrupts), and clears R=0.

(a) Instruction at address 1:
Address 1 should contain a BUN (Branch Unconditional) instruction to the interrupt service routine at address 230:
BUN 230 (or in binary: the BUN instruction with address field = 230)
This redirects control from address 1 to the start of the output program at 230.

(b) Last two instructions of the output program:
Before the output program returns to the interrupted main program, it must:
1. Re-enable interrupts: ION (I/O enable — sets IEN=1 so future interrupts can occur)
2. Return to the interrupted program: BUN I 0 (indirect branch through address 0, which contains the saved return address = the address in the main program where execution was interrupted)

Summary: Last two instructions = ION (re-enable interrupts) → BUN I 0 (return via saved PC at address 0)

I/O Programming

82%

Three Methods of I/O Data Transfer

The basic computer can interact with I/O devices using three methods. Understanding all three is important for RTU exams.

Three ways a computer can communicate with a keyboard or printer: (1) Keep asking "are you done yet?" (polling) — wasteful but simple. (2) Do other things and let the device TAP YOU on the shoulder when it's ready (interrupt) — efficient. (3) Let the device copy data DIRECTLY to memory without bothering the CPU (DMA) — fastest for large data. The basic computer uses the first two; DMA is covered in Unit 5/6.

1. Programmed I/O (Polling / Busy-Wait)

The CPU continuously checks the status flag of the I/O device (FGI or FGO) in a loop until the device is ready. Simple but wastes CPU time in the loop.

Input Program (Polling) — Read one character START, SKI / Skip next if FGI=1 (input device ready) BUN START / FGI=0: loop back and check again INP / FGI=1: read character from INPR to AC STA CH / Store character in memory HLT
Output Program (Polling) — Send one character LDA CH / Load character to send into AC START, SKO / Skip next if FGO=1 (output device ready) BUN START / FGO=0: loop back and wait OUT / FGO=1: send character from AC to OUTR HLT

2. Interrupt-Driven I/O

The CPU enables interrupts (ION) and continues executing the main program. When an I/O device is ready, it sends an interrupt signal. The CPU suspends the main program, saves the return address, and executes an interrupt service routine (ISR). After I/O, it returns to the main program.

Interrupt Mechanism — Hardware Sequence
When interrupt occurs (R=1, IEN=1, at end of current instruction):
1. M[0] ← PC (save return address at location 0)
2. PC ← 1 (jump to interrupt vector at address 1)
3. IEN ← 0 (disable further interrupts)
4. R ← 0 (clear interrupt request)
Address 0: always contains a BUN to ISR location. Address 1: BUN to interrupt service routine.
ISR ends with: ION (re-enable interrupts) + BUN I 0 (indirect return via saved address)

📝 RTU PYQs — I/O Programming
Q. What are the two instructions needed in the basic computer in order to set the E flip-flop to 1?
2023-Aug Part A Q7 · 2 marks ⭐⭐Register-Reference Instructions
The E flip-flop (extended accumulator / carry bit) can be set to 1 using two instructions:

Method 1:
1. CLE (Clear E) — first clear E to 0
2. CME (Complement E) — then complement E → 0 becomes 1
After CLE + CME: E = 1

Method 2 (using arithmetic overflow):
Load the maximum positive value (0111...1) into AC, then execute INC — the carry out sets E=1.

Most direct answer for RTU: CLE followed by CME. CLE sets E=0, CME flips it to E=1.
Q. What is the difference between a direct and an indirect address instruction?
2023-Aug Part A Q6 · 2 marks ⭐⭐Addressing Modes
Direct Address Instruction (I=0):
The address field of the instruction directly contains the EFFECTIVE ADDRESS of the operand. The CPU goes directly to that memory location to fetch the operand. One memory access needed.
Example: LDA 200 — operand is at memory address 200.

Indirect Address Instruction (I=1):
The address field contains the address of a POINTER — a memory location that contains the actual effective address. The CPU reads the pointer first, then uses that as the address to fetch the operand. Two memory accesses needed.
Example: LDA I 200 — memory[200] contains the ACTUAL address of the operand.

Key difference: Direct = 1 memory read for operand. Indirect = 2 memory reads (one for pointer, one for operand). Indirect adds flexibility (pointer can be changed at runtime) at the cost of one extra memory access.

Control Memory (Microprogrammed Control)

🔥 85% — Part A 2024
🔮
2026 Prediction — HIGH: Control memory appeared as Part A Q3 in 2024 ("What is a control memory?"). This is likely to repeat or expand into Part B as "Explain control memory with its structure" in 2026. Know the address size, word size, microinstruction fields, and how it relates to microprogramming.

What is Control Memory?

Control memory (also called Control Store or Microprogram Memory) is a small, fast memory inside the CPU that stores the microprogram — the sequence of microinstructions that implement each machine instruction. It is the core of a microprogrammed control unit.

Control memory is like a recipe book inside the control unit. Each "recipe" (microprogram) describes how to execute one machine instruction. When the CPU needs to execute LDA (Load Accumulator), it looks up the LDA recipe in the control memory and follows those micro-steps. Instead of hardwiring the control logic (like a fixed circuit), the microprogrammed approach reads from this memory book.
Control Memory — Structure
Control Memory: 2^k words, each word is one microinstruction
Control Address Register (CAR): k bits — holds address of next microinstruction
Control Data Register (CDR): n bits — holds current microinstruction
Each microinstruction word contains: F1, F2, F3: Micro-operation fields (specify operations to perform) CD: Condition code (for branching) BR: Branch type (determines next address mechanism) AD: Next address field
CAR is loaded with the address of the next microinstruction to execute — this is the address sequencing function

Microinstruction Fields

A typical microinstruction (as per Mano's basic computer) has 20 bits organized in fields:

FieldBitsPurpose
F13Micro-operations on AC, TEMP, DR (e.g., AC←0, DR←AC)
F23Micro-operations on AR, PC, DR (e.g., AR←PC, PC←PC+1)
F33Micro-operations on IR, PC from DR, other ops
CD2Condition for branching (00=always, 01=I-bit, 10=Negative, 11=Zero)
BR2Branch type (00=increment CAR, 01=unconditional branch to AD, 10=call, 11=return)
AD7Next address (for branch target)
Control Memory — Size Calculation
Total bits per microinstruction word = F1 + F2 + F3 + CD + BR + AD
= 3 + 3 + 3 + 2 + 2 + 7 = 20 bits per word
Address space: 7-bit AD → 128 locations (2⁷ words in control memory)
Total control memory size = 128 × 20 = 2560 bits = 320 bytes
Compare to RAM: RAM has 4096 × 16 bits = 65,536 bits. Control memory is MUCH smaller but faster.

Address Sequencing in Microprogrammed Control

80%

What is Address Sequencing?

Address sequencing is the mechanism by which the control unit determines the address of the NEXT microinstruction to execute. It answers: "After this microinstruction, which one runs next?"

Address sequencing is the GPS navigation system for the control memory. After executing one microinstruction (one step in a recipe), the control unit needs to know which step comes next. Sometimes it just goes to the next line (sequential), sometimes it skips to a different part of the recipe (branch), and sometimes it looks at the current instruction to decide which recipe to follow (mapping).

Four Methods of Address Sequencing

1. Incrementing the Control Address Register (CAR)

The simplest case: after executing the current microinstruction, increment CAR by 1 to go to the next sequential microinstruction. Like reading instructions on a list, one by one.

Sequential Execution
CAR ← CAR + 1 (move to next microinstruction in control memory)
BR field = 00: No branch — just increment CAR. Used for sequential micro-operations within one instruction's microprogram.

2. Unconditional Branch

The BR field specifies an unconditional branch — load CAR with the AD field of the current microinstruction (jump to a specified address in control memory). Used to repeat a sequence or go to a fixed subroutine.

Unconditional Branch
CAR ← AD field (load CAR with the next address from the microinstruction)
BR field = 01 (unconditional branch): always jump to AD, regardless of condition

3. Conditional Branch

Based on a condition (specified by CD field), branch or continue sequential. The condition can be the I-bit, the sign of AC, the zero flag, etc.

Conditional Branching
CD = 00: Always branch to AD (unconditional)
CD = 01: Branch if I = 1 (indirect bit of current instruction)
CD = 10: Branch if AC is negative (MSB = 1)
CD = 11: Branch if AC is zero
If condition is true → CAR ← AD. If false → CAR ← CAR + 1 (continue sequential)

4. Mapping from Instruction

When the CPU fetches a new machine instruction, it must find the starting address of that instruction's microprogram in control memory. This is done by MAPPING the opcode to a control memory address.

Mapping Function (Opcode → Control Memory Address)
Machine instruction opcode: I(1) | Opcode(3) | Address(12)
Mapping: CAR ← 0 | Opcode | 0 0 (insert 0s around the 3-bit opcode to form 7-bit address)
Example: ADD opcode = 001 → CAR = 0 001 00 = 0000100 = address 4 (decimal)
This puts each instruction's microprogram at a fixed, predictable location in control memory
The mapping logic uses a ROM or decoder to convert opcode → starting address in control memory

Microprogram Example

75%

Microprogram for the Fetch Cycle

Every machine instruction starts with the fetch cycle. In a microprogrammed control unit, this is implemented as a microprogram stored in control memory. The same fetch microprogram runs for every instruction.

Think of the fetch cycle microprogram as a standard breakfast routine — you always do the same thing first: wake up, brush teeth, etc. Similarly, every machine instruction starts with the same fetch microprogram: "go to the address in PC, read the instruction, bring it back to IR." After that, different instructions branch to their own specific microprograms.
Fetch Cycle Microprogram — Control Memory Example
Address | F1 | F2 | F3 | CD | BR | AD | Comment
00 | 000 | 001 | 000 | 00 | 00 | 000 | AR←PC (F2: transfer PC to AR)
01 | 000 | 010 | 001 | 00 | 00 | 000 | DR←M[AR], PC←PC+1 (F3: IR load; F2: PC incr)
02 | 000 | 000 | 010 | 00 | 10 | 000 | AR←DR(0-11), decode, BRANCH on opcode
At address 02: opcode mapping sends CAR to the correct microprogram for the current instruction

Microprogram for ADD Instruction

ADD Microprogram (starts at address 4 if opcode=001→mapping gives addr 4)
Address | Microoperations | BR type
04 | DR←M[AR] | CAR+1 (sequential)
05 | AC←AC+DR, if carry E←1 | Unconditional branch to 00 (back to fetch)
ADD takes 2 microinstructions after fetch: read operand, then perform addition
After ADD's microprogram ends (addr 05), BR field = unconditional branch → CAR ← 00 → start next fetch cycle

Hardwired vs Microprogrammed Control Unit

🔥 92% — EVERY EXAM
🔮
2026 Prediction — CERTAIN Part B: Hardwired vs Microprogrammed appeared in Part B Q6 (2022), Part A Q10 (2023-Aug), Part B Q4 (2025) — three different papers. It is the single most consistently tested Unit 3/4 comparison question. Draw both control unit structures and write a full comparison table. 4–8 marks depending on the part.

Hardwired Control Unit

In a hardwired control unit, the control logic is implemented entirely using combinational and sequential logic circuits (gates, flip-flops, decoders). The control signals are generated by fixed hardware — there is no memory or program; the logic is "wired in" permanently.

A hardwired control unit is like a microwave oven with physical buttons. Each button triggers a fixed, hardwired sequence of operations (heat for 1 min, buzz, stop). You can't change what the button does without opening the microwave and rewiring it. It's fast because the circuits are dedicated, but inflexible because changing behavior requires hardware modification.
Hardwired Control — Generation of Control Signals
Control signal = f(instruction, timing state, condition flags)
Example: T3 ∙ D0 → signal to read memory (DR←M[AR]) for AND instruction
T4 ∙ D0 → signal to AND AC with DR (AC←AC∧DR)
T0..T7 = timing states | D0..D6 = decoder outputs (one per opcode) | Conditions: E, N, Z, etc.
Implementation: Row Decoder + Combinational Logic + Encoder

Microprogrammed Control Unit

In a microprogrammed control unit, control signals are generated by reading microinstructions from a control memory. Each machine instruction is implemented as a sequence of microinstructions (a microprogram) stored in the control memory.

A microprogrammed control unit is like a programmable smart home system. Each "scene" (like "movie night") triggers a stored program of steps (dim lights, close blinds, turn on TV). You can add new scenes or change existing ones just by editing the program — no rewiring needed. The control memory IS the program; the hardware just reads and executes it.

Hardwired Control Unit:
Control signals are generated by combinational and sequential logic circuits — gates, flip-flops, and decoders permanently wired together. No program or memory is used. Control signals = f(opcode, timing state, condition flags). Very fast but inflexible.

4. Usage: Hardwired → RISC (ARM, MIPS); Microprogrammed → CISC (Intel x86)
5. Fault correction: Hardwired requires hardware fix vs Microprogrammed just updates memory
6. Instruction set changes: Hardwired cannot add instructions vs Microprogrammed can add new microprograms

Q. Explain the concept of microprogrammed control unit.
2022 Part A Q7 · 2 marks ⭐⭐Microprogrammed CU
A microprogrammed control unit implements the control logic using a small, high-speed memory called control memory, which stores microprograms — sequences of microinstructions that define how to execute each machine instruction.

Key components:
1. Control Memory: Stores all microprograms. Each word = one microinstruction (20 bits in the basic computer).
2. Control Address Register (CAR): Points to the next microinstruction to execute.
3. Control Data Register (CDR): Holds the current microinstruction being executed.
4. Address Sequencer: Determines the next value of CAR (sequential, branch, or mapping).

Operation:
When a machine instruction is fetched (e.g., ADD), its opcode is mapped to a starting address in control memory. The control unit reads microinstructions from that address sequentially, generating control signals to perform micro-operations until the instruction is complete. Then it branches back to the fetch microprogram.

Advantage over hardwired: Instructions can be added or modified by changing microcode without redesigning hardware.
Q. Give an example of a RISC I instruction that will perform the following operations: (a) Decrement a register, (b) Complement a register, (c) Negate a register, (d) Clear a register, (e) Divide by 4, (f) No operation.
2023-Aug Part C Q3 · 15 marks ⭐⭐RISC I Instructions
RISC I uses 3-operand instructions of the form: OP dest, src1, src2 (or immediate).

(a) Decrement register R1:
SUB R1, R1, 1 / R1 ← R1 − 1 (subtract immediate 1 from R1)

(b) Complement register R1 (1's complement):
XOR R1, R1, -1 / R1 ← R1 XOR 0xFFFF... (XOR with all-1s flips every bit)
OR: NOT R1, R1 / if NOT instruction available

(c) Negate register R1 (2's complement = -R1):
SUB R1, R0, R1 / R1 ← 0 − R1 = −R1 (assuming R0 is always 0)
OR: XOR R1, R1, -1 then ADD R1, R1, 1

(d) Clear register R1 (set to 0):
XOR R1, R1, R1 / R1 ← R1 XOR R1 = 0
OR: MOV R1, R0 / Move 0 (from R0) to R1

(e) Divide by 4 (for signed numbers):
SRA R1, R1, 2 / R1 ← arithmetic shift right by 2 positions = R1 ÷ 4
(Arithmetic shift right preserves sign bit for signed numbers)

(f) No operation (NOP):
ADD R0, R0, 0 / R0 ← R0 + 0 = R0 (no change, writes to R0 which is always 0)
OR: MOV R0, R0 / Move R0 to itself — no effect
